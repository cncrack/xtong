## 零、为什么必须并行（用户强调）

> 「7 个账号要多开时只能排队…后面可能会更多账号，这个我们在先前设计与开发的时候已经说过了，账号数量比较多」

现有结构是**全局单点**：进程内互斥锁 → 写唯一一个 `chrome_start.json`（后写覆盖前写）
→ 触发唯一一个任务。7 个账号只能排队（每个 10~40 秒），且任何一次失败会污染下一个。
**账号越多越不可用**，必须改成按账号隔离 + 真并行。

## 一、查证基础（已实测）

| 项 | 结论 |
|---|---|
| `label` 是什么 | **账号代号**，不是序号、不是端口。正则 `^[a-z0-9][a-z0-9_-]{0,23}$` |
| label 同时用在哪 | profile 目录 `data/profiles/<label>`、节缓存 `sections_<label>_*.json`、账本 `account` 字段、登录态快照 |
| 中文能否做 label | **不能**：`accounts.py:108` 解析时直接跳过；`gxks_questions.py:40` 抛「账号必须使用本地代号」 |
| 7 个账号端口 | 9222 / 9233 / 9288 / 9225 / 9283 / 9267 / 9250（互不相同） |
| 任务运行中重复 `/run` | 实测 **rc=0**，只多一行 `INFO: currently running.` → 不是失败原因 |
| 那次的失败 | `chrome_start.json` 21:08:31 写入、`result.json` 21:10:51 才出现 → 中间 `/run` 失败；**但代码一律报「任务不存在」**，这是误导的真 bug |
| 拼音库 | `pypinyin` / `xpinyin` 均未安装；标准库 `unicodedata` **只给码点名称、不含拼音** → 用户选择不加依赖 |

## 二、方案 B：每账号一个计划任务

### 2.1 命名与文件隔离

| 项 | 现状 | 改后 |
|---|---|---|
| 计划任务 | 全局 `xxt-gxks-chrome` | **`xxt-gxks-chrome-<label>`**（如 `xxt-gxks-chrome-jia`） |
| spec | `data/tmp/chrome_start.json` | `data/tmp/chrome_start_<label>.json` |
| result | `data/tmp/chrome_start.result.json` | `data/tmp/chrome_start_<label>.result.json` |
| 并发 | `_CHROME_START_LOCK` 串行 | **删掉该锁**（注册另有锁，见下） |

**`-Label` 写进任务动作**（不是运行期传参）：
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File <root>\scripts\start_chrome.ps1 -Label <label>`

→ 每个任务各读各的 spec，**互不覆盖**；某账号失败不影响其他。

### 2.2 自动注册（选 C：预注册 + 懒注册）

```
_ensure_chrome_task(label)：
  schtasks /query /tn xxt-gxks-chrome-<label>
    存在 → 直接返回 ok
    不存在 → 用 PowerShell ScheduledTasks 模块注册（当前用户/Interactive/Limited）
             注册成功 → ok
             注册失败 → 返回可照做的手工命令 + 原始 stderr
```

- **面板启动时**：遍历账号表，逐个 `_ensure_chrome_task`（缺的补上）
- **新增账号保存时**：为新账号注册一个
- 注册走 `_TASK_REGISTER_LOCK`（**只串行注册，启动并行**）

### 2.3 报错如实化（这次误导的真 bug）

| 情况 | 判断依据 | 返回 |
|---|---|---|
| 任务不存在 | stderr 含 `cannot find` | 给手工注册命令 |
| 任务在跑 | stdout 含 `currently running` | **不报错**，等待其完成 |
| 权限不足 | stderr 含 `Access is denied` / `拒绝访问` | 「请以管理员身份运行面板」 |
| 其他 | 兜底 | **原样带出 stdout + stderr** + 排查命令 |

**关键**：`schtasks` 原始输出必须一并回传 —— 这次误导正是因为把它丢了。

### 2.4 状态自检（可观测）

`/api/state` 的 `browser` 块增加：

```json
"chrome_task": {"name": "xxt-gxks-chrome-jia", "registered": true, "state": "Ready"}
```

面板「浏览器与会话」区显示一行：
`交互式任务：已注册（Ready）` / `未注册（首次启动时自动注册）`

→ 下次出问题一眼看到任务状态，不用猜。

## 三、label 自动生成（`user01` 递增）

### 3.1 规则

```
新增账号时：
  填了代号 → 用之（校验合法性 + 唯一性，与现在一致）
  没填代号 → 自动生成：user01、user02、user03…（取第一个未被占用的）
```

### 3.2 为什么不加拼音库（用户决定）

- `pypinyin` 可转拼音，但要新增第三方依赖（AGENTS 约定需同意），且多音字/重名仍需兜底
- 用户选择：**不加依赖**，直接用 `userNN` 递增
- 中文名继续放 `display`（面板「账号」列显示的就是它，所以看得出是谁）

### 3.3 落点

| 位置 | 改动 |
|---|---|
| `accounts.py` | 新增纯函数 `suggest_label(existing: list[str]) -> str`：扫已有 label，返回第一个空闲的 `userNN`（补零两位，超 99 用三位） |
| 面板「新增账号」表单 | 代号留空时，保存前自动填入（前端调一次 `suggest_label` 或由后端兜底） |
| 后端 `save_account` | **兜底**：`label` 为空时自动 `suggest_label`，不报错 |

**兼容**：现有 7 个账号一个都不动。
