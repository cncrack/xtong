> 用户 2026-11-28：「有没有办法在第一次做的时候就能达到百分百正确？
> 有更好的做题方案或者优化吗？」→ 提了「交卷前二次验证」→ 用户拍板「可以开始」。

---

## 一、要解决的具体错误

1.6 第 2 题：`2025年是人民海军成立75周年。`
平台标准 = **错**（人民海军 1949-04-23 成立，2025 年是 76 周年）。

**AI 的 reasoning 原文**：
> 「人民海军成立于1949年，**2024年为75周年，题目表述有误**，
> 但根据常见公考题库逻辑，此处可能指2024年，或题目本身年...」

**它自己算出不对，还是答了「对」。** 这是「替题目圆场」——第一次作答时
模型倾向于把题做对，会为异常找理由。

---

## 二、做法：换个角色再问一遍

```
第 1 遍（作答者）：正常答题 → 「对」，confidence 0.95
      ↓
第 2 遍（校对者）：换个 prompt，让它挑毛病
      → 「错：1949+75=2024，差一年」
      ↓
比对：一致 → 高可信；不一致 → 面板标红
```

**为什么必须换 prompt**：同一段 prompt 问两遍，模型会给同样的答案，什么都没验到。
`build_verify_messages()` 的措辞是「你是在校对一份已作答的测验…请独立核对，
不要假设原答案正确」，并针对判断题要求「逐字核对每个要件，不得替题目圆场」。

---

## 三、三条硬规则（都是刻意的）

### ① 题库命中的题**不验**

平台官方答案就是权威，AI 没资格质疑它。验了反而可能把正确答案改错。
**顺带省钱**：题库命中的题一次 LLM 都不调。

### ② 不一致时**不自动改答案**

`keys` 保留**第一遍**的结果，只在 `verify.suggested` 里记「校对者认为是 X」。

**理由**：自动改等于用第二个可能错的答案替换第一个。改不改由人决定。

### ③ 验证出错**不影响主流程**

任何异常都吞掉，只记 `verify.error`。决不能让「锦上添花的检查」把整卷弄挂。

### 一个细节：`agree` 缺省时自己推断

模型不一定老实回 `agree`。所以：
```python
if not isinstance(agree, bool):
    agree = bool(v_keys) and v_keys == keys     # 比信任模型自报更稳
```
