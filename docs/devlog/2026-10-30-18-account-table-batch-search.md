# 2026-10-30-18 账号区改表格 + 多选批量 + 搜索筛选 + 悬停详情

## 一、起因

用户先问：「账号与任务这个区域每个账号弄成表格形式的，一个账号占一行或者两行表格，
你觉得会不会更合理，简单方便，多账号管理会更方便，在这个固定区域内当账号多的时候可以出现
滚动条，也要考虑加上选择可多选统一操作，比如启动，暂停、查找，搜索按关键字，筛选等扩展功能。」

我实测后**同意这个判断**，并用数据说明理由（见 §二），用户随后确认了四项决策：

| 决策 | 用户选择 |
|---|---|
| 视图 | **表格 + 悬停展开详情**（鼠标移开自动隐藏），不要卡片 |
| 每行信息量 | 单行 + 悬停详情，不要静态两行 |
| 批量动作 | 开始 / 停止 / 启用 / 停用 / **删除**（全要） |
| 搜索筛选 | 关键字搜索 + 状态/端口/凭据筛选 + **预设快捷筛选** |

## 二、为什么表格更好（实测数据）

| 视图 | 每行高 | 6 个账号 | 20 个账号 |
|---|---|---|---|
| 卡片（改前） | ~222px（6 栏宽下每行 2 张） | ~700px | ~2300px |
| 表格（改后） | **55px** | **330px** | **1040px（卡内滚动）** |

不只省空间，还有三个卡片做不到的事：

1. **可比较**：表格列对齐，「谁的额度用完了」「谁端口没开」扫一眼就能看出；卡片是独立小块，只能一张张读。
2. **多选天然**：复选框就是表格的一列；卡片要加复选框只能挤在卡片头上。
3. **搜索/筛选天然**：有列才能"只看运行中"；卡片只能整块显示或隐藏。

⚠ 连带变化：**账号区从 6 栏改为整行（span 12）**。表格 9 列约 940px，挤到 600px 会折行。
上一轮为"两列等高"加的 `main{align-items:stretch}` 与 6+6 并排已撤掉——问题从根上消失了。

## 三、改了什么

### 1. 表格（`acctTr`）

列：`☐ | # | 账号 | 端口 | 状态 | 今日 | 课程 | 登录 | 操作`

- **账号**列：显示名 + 第二行小字「学校 · 专业 · 年级」（静态摘要，超长截断 + title 看全）
- **今日**列：`3/10 节` + 一个 34px 的小进度条 + 分钟数
- **状态**列：运行中 / 空闲 / 已停用 / 额度用完（四态，由 `acctStatus()` 统一判定）
- **操作**列：学习 n 节 / 停止、刷新、✎、停用/启用、删除

### 2. 悬停详情浮层

鼠标划到行上 → 右侧浮出完整信息（序号/学校/专业/年级/学号/自定义字段/今日/课程/登录快照/凭据/正在跑的任务），
**移开自动隐藏**。

两个刻意的选择：

- 浮层 `pointer-events:none` —— 它不拦鼠标，所以"移开行"**一定**触发 mouseout，不会卡住；
- 空间不够时自动翻到行的左侧，并且纵向贴边（不会超出视口）。

### 3. 多选与批量

- 表头复选框 = 全选**当前可见**（筛选后只选筛出来的）；
- 选中集合 `SEL` 记在 JS 里 —— 表格每 4 秒整块重绘，靠 DOM 会丢（与 `SEC_OPEN` 同一教训）；
- 批量栏显示「已选 N 个」+ 六个按钮（开始/停止/启用/停用/删除/取消选择）；
- **批量删除二次确认**：前端 `confirm` 列出要删的代号，后端再要一次 `confirm` 标记。

### 4. 搜索与筛选

- **搜索**匹配：名称 / 代号 / 端口 / 课程 / 序号 / 学校 / 专业 / 年级 / 学号 / **自定义字段的键和值**
- **三个下拉**：状态（运行中/空闲/已停用/额度用完）、端口（活着/未监听）、凭据（已配置/未配置）
- **预设快捷**：运行中 / 额度用完 / 端口没开 / 无凭据 / 清空
- 工具栏 DOM 放在轮询重绘的容器**外面** —— 否则每 4 秒搜索框掉一次焦点，没法打字。

### 5. 后端批量接口 `POST /api/accounts/batch`

- 语义与单个操作**完全一致**：抽出 `_study_one()` / `_stop_one()` 供 `/api/study`、`/api/stop` 与批量共用
  （不抽的话批量那条路早晚走偏，比如漏掉"在跑就不重复起"）。
- **一个失败不影响其它**：逐个收集结果，汇总里说清谁成了、谁没成、为什么
  —— 批量最怕"第 3 个报错，后面全没做"。
- **未知代号整批拒绝**：宁可什么都不做，也不静默只跑存在的那几个。
- 删除两道闸：必须 `confirm` + 不许删光。

### 实跑揪出的两个问题（都已修）

1. **多选完全不生效**：复选框所在的 `<td>` 上写了 `onclick="event.stopPropagation()"`
   （本意是挡住"点复选框顺手切账号"），结果把**委托到 `#accounts` 的 click 监听也挡掉了**。
   修法：行点击也改成委托，在同一个 handler 里分流——先判 `#acct-all`、再判 `.acct-pick`、
   再 `closest("button")` 直接 return、最后才 `pick()`。`<tr>` 与 `<td>` 上的 inline onclick 全部删掉。
2. 批量测试里 `a3` 夹具本来就是停用状态，断言"一个都没动"时不能拿它当证据（改成只查 a1/a2）。

## 五、关键决策及理由

1. **表格替代卡片，不是二选一开关**：用户明确要表格；留一个视图开关只会多一份要维护和测试的分支。
2. **账号区整行独占**：9 列约 940px，600px 会折行；顺带解决上一轮的"左右不等高"。
3. **行点击走事件委托**：表格每 4 秒重绘，inline onclick 与直接绑定都会随重绘失效；
   而且委托是"复选框多选"能工作的前提（见 §四 问题 1）。
4. **浮层 `pointer-events:none`**：不拦鼠标才能保证"移开必隐藏"，不会出现浮层挂在屏幕上不走。
5. **批量与单个共用同一段逻辑**：避免两条路走出两种语义。
6. **未知代号整批拒绝**：静默部分执行会让人以为"都跑上了"，比直接报错更危险。

## 七、已知边界

1. **批量「开始学习」固定跑 3 节**（`max_sections=3`），面板没有让用户选每号跑几节；
2. **悬停详情是纯展示**，里面没有可点元素（要操作请用行内按钮或 ✎ 编辑）；
3. **筛选状态不持久化**：刷新页面回到"全部"；
4. **搜索无防抖**：账号量极大时每敲一个字都重绘一次（当前规模无感，几百个账号可能需要加）；
5. **排序功能没做**：当前按账号表顺序（即序号），点列头排序未实现。
