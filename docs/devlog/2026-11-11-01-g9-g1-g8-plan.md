### 第 0 级：`off`（当前，默认）

### 第 1 级：`review`（**本轮建议落地**）

脚本填完 → **产出一份「交卷前核对单」**并写进面板，等人确认。核心是**把「不确定性」显式化**：

| 判据 | 来源 | 触发「必须人工确认」 |
|---|---|---|
| `source=ai` 的题数 > 0 | `plan_answers` 结果 | ✅ AI 推理题一律需人看 |
| 任一题 `confidence < 阈值`（建议 0.85） | 同上 | ✅ 低置信一律需人看 |
| `bank` 命中率 100% | 同上 | 可标「题库全命中，可信度较高」 |
| 题型不在 `allowed_types` | 已实现 | ✅ 整卷拒填（现有行为） |
| 回填后 `read_checked` 不一致 | 已实现 | ✅ 抛错（现有行为） |

**产出**：`work_*.json` 里加 `review` 字段（建议人/理由/每题风险），面板「本次作答」区显示一行醒目的
「⚠ 3 题需人工核对（2 题 AI / 1 题低置信）」+ 可展开的逐题风险表。
**仍不自动交卷**；`gx_ops` 新增动作 `work-review`（待确认）。

### 第 2 级：`guarded`（**留接口，暂不启用**）

只有**全部题目 `source=bank` 且题库答案是 `standard_source='site'`**（平台判分客观答案）、

  `lookup_answer` 只认 `site` 的设计（`gxks_questions.py:215-220`），不用改题库结构

# 二、G-1 重启面板按钮

## 难点（必须说清）

`serve()` 用 `uvicorn.run(reload=True)`，在 Windows 是**多进程树**：
`xxt.exe → python(重定向器) → python(reloader) → python(spawn worker)`。
面板自己是个 FastAPI 进程，**不能在请求里直接重启自己**（请求还没返回进程就没了，
前端会看到「连接中断」；且 `reload=True` 的 reloader 父进程只要活着就会再 spawn 一个 worker）。

## 建议方案：**「请求重启」+ 延迟退出 + 前端自动重连**

| 步 | 实现 |
|---|---|
| 1 | 新增 `POST /api/panel/restart`：写一条 `panel-restart` 操作记录（留痕），返回 `{ok:true, retry_after: 3}` |
| 2 | 后端用 `threading.Timer(0.5, ...)` 延迟，调 `os._exit(0)` 结束**当前 worker 进程**；`reload=True` 的 reloader 检测到 worker 退出会**自动 spawn 新 worker**（这正是热重载的机制，不需要外部脚本） |
| 3 | 前端收到回包后显示「面板正在重启…」，按 `retry_after` 轮询 `/api/state`，**恢复后自动 `location.reload()`** |
| 4 | 按钮放「账号设置 → 面板设置」卡片里，紧挨「热重载」开关；**二次确认**（`confirm("确定重启面板？刷课任务不受影响")`） |
| 5 | **安全边界**：只结束 worker、不碰刷课子进程（`_spawn_script` 已加 `DETACHED_PROCESS`）；reloader 没起来时按钮置灰并提示「请在自己的 PowerShell 窗口重启」 |

**风险**：Windows 下 `os._exit` 会不会连 reloader 一起带走，需要实机验一次。
**兜底**：若实测 reloader 不复活，改成写 `data/run/panel_restart.flag` + 面板启动脚本检测（更绕），
或干脆按钮只做「提示用户按 Ctrl+C 重启」+ 一键复制命令（零风险但体验差）。
→ **建议先按主方案实机验，验不过走兜底。**

2. 是否接受「实机验一次」这个前置（需要你在自己窗口起面板）？
