## 三、重大发现：#1 刷不到东西的真因（与昨日推测不同）

读 `data/logs/sub-mlearn-20261027-110625.log`（11:06 那次补跑），实况与我 27-09 里"4.5 是非视频任务点"的推测**完全不符**：

```
11:07:43 进入知识点：第四章｜5.1 改变学习方法（上）（1227271614）
11:07:47 [改变学习方法（上）] 开始播放：倍速 1.13
11:07:50 进度 3/551s
...（正常推进）
11:17:09 进度 441/551s
11:17:26 播放结束（ended=False）        ← 441/551 就结束了
11:17:36 watcher 注入失败（跳过）
11:17:52 下一节按钮不可点 → 改从章节列表进下一节：5.1 改变学习方法（上）
11:17:52 点击知识点 1227271614 失败：Frame was detached
11:17:52 ...（5.1、5.2、5.3 全部 Frame was detached）
         视频 0 个；连续 3 节都打不开任务页
```

即：**5.1 是能打开、能播的**，问题出在"播到 441 秒异常中断"之后。由此查出 3 个真 bug：

| 编号 | Bug | 证据 | 后果 |
| --- | --- | --- | --- |
| **B1** | `tree_frame` 只在开头取一次（astudy.py:314），iframe 重建后不重取 | 3 次点击全报 `Frame was detached` | 任何"页面重载"都会让后续点击全失败，误判为"这几节都打不开" |
| **B2** | `_jump_next_pending` 查的是**全表第一个 `pending`**，不看当前 idx；且失败就 `mark_entry_visited(only_pending=True)` | 它回头去点**当前这一节 5.1**；失败后把已是 441/551s 的 5.1、5.2、5.3 全标成 `visited` | ① 反复撞同一节 ② **把没看完的 5.1 永久跳过**：`chapters` 里 5.1/5.2/5.3 现在是 `visited`，明天会从 5.4 开始，5.1 剩下的 110 秒再也不会补 |
| **B3** | `ended=False` 且进度未达标时，不重试续播，直接换下一节 | 441/551s 结束，`is_plausible_completion` 不记 `video-done`（正确），但也没有第二次机会 | 每次会话白跑到中断点就收工，看起来"刷了 7 分钟、视频 0 个" |

另：`watcher 注入失败（跳过）` 出现在 11:17:36 —— 播放结束、页面状态变化后注入失败，与 B1 同源（frame 被换掉）。

## 四、待用户拍板的两个问题

### 问题 1：卡片徽标"刷课中"与"已登录"互斥

现状（`renderAccounts` 的 `.state`）：`run ? badge('刷课中 '+since) : sess`，其中 `sess` = `已登录/未登录`。所以：

- **在刷** → `active` + `刷课中 11:06`（**没有**「已登录」）
- **没刷** → `active` + `已登录`

这是刻意设计（正在刷 ⇒ 会话必然有效），省一个徽标位置。可选改法：

| 方案 | 效果 | 代价 |
| --- | --- | --- |
| 维持现状（推荐） | 头部 2 个徽标，最省空间 | 刷课时看不到"已登录"字样 |
| 两者并存 | `active` + `已登录` + `刷课中`（3 个） | 410px 最窄卡片上会把姓名挤成两行 |
| 折中 | 维持互斥，但给「刷课中」徽标加 hover 提示"已登录" | 零空间代价 |

### 问题 2：B1~B3 的修复范围

| 方案 | 内容 | 工作量 |
