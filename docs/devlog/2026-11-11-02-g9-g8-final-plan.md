## 一、查证：客观题「提交后入库」的现状

| 事实 | 位置 |
|---|---|
| 判分页解析出 `standard`（平台标准答案）、`is_correct`、`score_got` | `adapters/gxks/practice.py:181-203`，读 `<span class="tmda">标准答案</span>` |
| 导入时**整份答卷**入库（含答错的题），`standard_source='site'` | `store/gxks_questions.py:148-155` |
| `lookup_answer` **只认 `standard_source='site'`**，按题干+选项逐项校验 | `gxks_questions.py:215-257` |
| 题目 `gx_q_items` 按 `platform_qid + fingerprint` 唯一，**不带账号/课程** → **多人同课天然共用一份题库** | `schema_gxks.py:22-31` |
| 答卷 `gx_q_papers` 按 `UNIQUE(account_label, exam_start_id)` 隔离 | `schema_gxks.py:40-51` |
| `type_code` / `type_map` 已有（页面自带 13 种题型） | `practice.py:194-195` |
| 导入通道是**离线脚本** `scripts/import_gxks_practice.py`，需 `--capture-dir` | 该脚本 L16-52 |

### 两个必须补的缺口

1. **「答案正确才收入、主观题不收」没有显式闸门**。现在 `import_bundle` 把答错的题、
   主观题一股脑入库；`lookup_answer` 虽只认 `site`，但主观题的 `standard` 也会被写进去，
   将来被别的账号误用。→ 补 `objective_registry`：按 `type_code` 判定客观题，
   只有客观题 + `standard_source='site'` 才进共享答案池。
2. **自动入库接线缺失**（G-7）：`gxks_work.py` 只有 `lookup_answer` 查库，
   没有「提交后回读判分页 → 入库」的代码。→ 本轮补**接线骨架**（不自动触发，
   由人工点「回读判分」或 G-5 实跑后触发）。

### 关于「你怎么知道平台标准答案」

**只能从平台判分页回读**（`practice.parse_capture`），不是 AI 推的、不是猜的。
所以「成熟」的客观判据是：**该 `exercise_id` 下每道题在题库里都有 `site` 标准答案**，
不是「课程累计 N 题」，也不是 `confidence`。

### 关于 `confidence`

`confidence` 是 **LLM 自报的主观确定度**（`gxks_work.py:69-88` 的 `data.get("confidence", 0.0)`），
**不是答案准确率、无校准**。
→ **不作自动闸门**，只作「模型自己说不太确定」的**展示提示**。

## 二、G-9 定稿：三级闸门（修正版）

| 级别 | 判据 | 行为 |
|---|---|---|
| **0 `off`**（默认） | — | 填完 → 断 CDP → **人自己核对并点交卷**（现状不变） |
| **1 `review`**（本轮落码） | 有 AI 题 / 无 `site` 标准答案 / 题型未实测 | 产出「交卷前核对单」+ 建 `gx_pending`，**仍不自动交卷**；提示精确到账号/课/节/题 |
| **2 `guarded`**（只留接口，不启用） | **整卷每一题都是客观题 + 题库里有 `site` 标准答案**（来自别的账号做对提交后的入库） | 才允许自动交卷；启用另需：人工核对 ≥10 次零误填 + 用户书面同意 |

**关键修正（相对 01 讨论稿）**：
- ❌ 删掉「`confidence` 全 1.0」—— 做不到也无意义
- ❌ 删掉「课程累计 30 题」—— 粒度太粗
- ✅ 改成「**按题**判断是否有 `site` 标准答案」，复用 `lookup_answer` 现有语义
- ✅ 客观题入库规则按用户定案：**做对提交 → 标准答案入共享池 → 其他账号同课直接调用**

## 三、不确定性按题型分（用户 10:54 要求）

| 题型 | 处置 |
|---|---|
| **客观题**（单选/多选/判断） | 答案唯一、要么对要么错，**没有重生成空间**。有 `site` 标准答案 → 采信；无 → 标「待验证」→ AI 生成 → **人核对** → 核对通过后可回写题库 |

→ 「逐题重新生成」做成**扩展点**（接口 + 前端按钮占位，G-6 放开题型后启用），本轮不实做。

## 四、G-8 定稿：`gx_pending` 表 + 三类留痕 + 跳过继续

### 4.1 表结构（新建，schema v3 → v4）

| 字段 | 用途 |
|---|---|
| `id` / `created_at` / `updated_at` | 主键与时间 |
| `account_label` / `course_id` / `section_id` / `section_name` / `exercise_id` | **定位：哪个账号、哪门课、第几节、哪个练习** |
| `question_ordinal` / `type_code` / `stem` | **定位到具体哪一题** |
| `reason` | `ai_used` / `no_site_answer` / `low_confidence` / `type_blocked` / `check_mismatch` |
| `risk_json` | 逐题风险（source / confidence / reason） |
| `work_file` | 指向 `data/debug/work_*.json` 完整快照 |
| `status` | `pending` / `verified` / `skipped` / `expired` / `submitted` |
| `decided_by` / `decided_at` / `decision_note` | **谁、何时、怎么决定**（留痕核心） |
| `op_id` | 关联 `gx_ops.id` 回溯整条链 |

### 4.2 三类留痕（全部可查）

| # | 留痕 | 落点 |
|---|---|---|
| 1 产生 | 填完自动建 `pending`，写清风险与定位 | `gx_pending` + `gx_ops(work-review)` |
| 2 决定 | 核对通过 / 跳过 / 转人工，记人、时间、备注 | `decided_*` + `gx_ops(work-verify/work-skip)` |
| 3 终态 | 交卷 / 过期 | `gx_ops(work-submit)` / `status=expired` |

### 4.3 三档处置（修正版）

| 档 | 行为 | 默认 |
|---|---|---|
| ~~A 停着等~~ | 挂起不继续 | ❌ 去掉（用户明确反对） |
| **A′ 提示 + 跳过继续** | 明确写出「**哪个账号 · 哪门课 · 第几节 · 第几题 · 什么问题**」，标 `pending`，**继续下一题/下一节，不阻塞** | ✅ 默认 |
| B 超时 | N 小时后标 `expired`，留痕 | 可选 |
| C 转人工 | 标 `skipped` + 提示手动完成 | 兜底 |

**不管人工还是无人值守都一样**：不催、不超时自动提交、不静默跳过。

### 4.4 放哪里 / 多账号

- **放进现有的「本次作答」区**（`renderWork`），不新建区域：
  逐题表加「风险」列 + 顶部「⚠ 待确认 N 题」+ 展开的待确认清单
- **多账号**：按 `account_label` 分组 + 顶部红点总数 + 复用 T5 的过滤下拉；
  不叠页签（N 大时失效）

### 4.5 与 G-9 的关系

共用同一份 `risk_json` 与 `work_*.json` 快照：
- 第 1 级：所有不确定单子进 `gx_pending`
- 第 2 级：满足「全客观题 + 全有 `site` 标准答案」的单子绕过队列走 `guarded`
