## 三、为什么不直接把 75 改成 300

我第一版方案就是写死 300，**但那是错的**：
- 11-08 那种 60 秒节奏会变迟钝 5 倍（真断网 5 分钟才发现）

所以改成**自适应**。

## 四、自适应怎么做（`report_stale_threshold`）

```python
# 每次上报真的增加，记一次真实间隔
update_intervals.append(now - last_update_at)

# 阈值 = 最近 5 次间隔的最大值 × 2.5，夹在 [75, 600] 秒
threshold = max(最近5次) * 2.5
```

**平台快 → 样本小 → 阈值收窄；平台慢 → 样本大 → 阈值放宽。**

### 实测验证

| 场景 | 观察到的间隔 | 自动阈值 | 结果 |
|---|---|---|---|
| 11-08 下午 | 60~65 | **150 秒** | 不误报 ✅ |
| 11-08 晚 | 60~73 | **150 秒** | 不误报 ✅ |
| 11-28 今天 | 103~133 | **332 秒** | 不误报 ✅ |

### 还剩下一个漏洞：**启动阶段**

第一次上报之前没有任何样本，只能落回 75 秒——而今天首次上报要 120 秒，
**仍然会误报一次**（日志里 14:29:18 那条就是）。

修：无样本时阈值 = **已等时长 × 1.5**，封顶 240 秒：

| 已等 | 阈值 | 报警? |
|---|---|---|
| 75 秒 | 112 秒 | 否 |
| **120 秒**（首次上报时刻） | **180 秒** | **否** ✅ |
| 250 秒 | 240 秒（封顶） | **是** ✅（真断网仍能发现） |
