## 一、用户的三个观察（都对）

### ① 「这个课程就是要先看完视频才能完成当节的练习」

**这是平台的硬规则**：每节的课后练习要**视频学完才解锁**（`practice_locked=true`）。

所以两种任务是**串行**的：

```
看视频（把本节学时刷够） → 解锁 → 做练习（AI 填答案 + 人核对 + 交卷）
```

### ② 「如果视频全部学习完了，就不能是在找未完成的节吧」

`default`（林鑫阳）36 节全学完，所以「列表里没有未完成的节」是**正确结果**，
但原来的措辞读起来像出错：

```
[DONE] 列表里没有未完成的节了（已翻完所有页）
=== 本次汇总 ===
  （没有完成任何节）
总耗时 0.6 分钟
```

### ③ 「选择哪个模式，是根据需要或者用户来选择的」

**对。逻辑没问题，是入口没区分清楚。**

## 三、为什么不做方案 B（统一的「模式选择」入口）

用户问过「要不要合并成一个入口」，我建议不合并，理由是**粒度不同**：

| 操作 | 粒度 | 例子 |
|---|---|---|
| 启动并看视频 | **账号级** | 「这个账号去刷视频」 |
| 做练习 | **节级** | 「这一节的课后练习」 |

**一个账号可能同时：某些节在学、某些节可以做练习。** 硬塞进一个「模式选择」
反而要求用户先想清楚"我现在是账号模式还是节模式"，更绕。

**所以文案说清就够了。**
