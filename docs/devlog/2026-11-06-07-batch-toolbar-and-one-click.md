# 2026-11-06-07 卡片内批量工具条 + 一键「启动并学习」

## 一、用户提问（四个问题）

> 「如果是有多个账号的话，右侧栏的浏览器与会话可以一键启动多个账号吗，还得要怎么去启动吗？
> 如果一个一个去点启动并登录，那也挺麻烦的，是否可以优化？
> 开始学习与启动并登录之间的关系是如何的？先登录才能学习吗？
> 那如何解决选择的多个账号登陆问题呢？」

### 逐条回答

1. **右侧栏不能一键启动多个** —— 那张卡片一次只显示**一个**账号（跟随选中/悬停），
   只有单个「启动并登录」。批量入口在**表格**里（批量栏的「启动浏览器（N 个没开）」），
   必须先勾选才出现 —— 两个场景在界面上是割裂的，这确实麻烦。
2. **关系是强依赖**：`run_gxks.py` 第一步就 `connect_over_cdp` 连 Chrome。
   没浏览器 → 立刻 `[FAIL]` 退出。**所以「必须先有浏览器」**，这是机制决定的事实。
   不能跳过「启动并登录」直接「学习」，除非你自己手动开过 Chrome 并保持。
3. **多账号登录问题**：每个账号有**自己的** Chrome + 自己的 profile + 自己的登录态快照
   （`data/storage_state_gxks_<label>.json`）。启动时自动注入快照；快照失效则用
   该账号自己的账号密码自动重登。所以"多账号登录"不是共享一份登录态，而是各管各的 ——
   不需要你逐个登录，只需要**逐个把浏览器拉起来**（这一步才是繁琐的）。

## 三、做了什么（A + B，用户多选）

### A. 卡片内加批量工具条

在「浏览器与会话」卡片里新增第三组按钮（原来是「浏览器」「会话」两组）：

```
批量 [全选待启动]  已选 N 个（甲、乙、丙）  [批量启动浏览器] [一键启动并学习] [批量停止]
```

- **全选待启动**：只挑**还没在跑**的账号（在跑的再选只会被跳过，选了没意义）；
  再点一次 = 取消。
- **独立的 `BATCH_SEL`**：**不复用**表格的 `SEL`。
  理由：表格那套是"账号管理"用途（启停/启用/删除），这套是"浏览器与学习"。
  混用会导致「表格勾了 3 个准备删除，右侧栏突然也在批量里算 3 个」。
- 未选中时三个按钮 `disabled`（避免点了没反应）。
- 窄屏按 AGENTS 界面约定：`flex-wrap:wrap` + 按钮最小 38px 高（手指可点）。

### B. 一键「启动并学习」

**后端** `_start_and_study_one(settings, label, run_session=..., max_sections=..., wait_seconds=45)`：

1. 该账号已在跑 → `skipped`（连点两下不会起两个）；
2. 端口没活 → `_browser_start_one` 起浏览器（**与单个「启动并登录」同一段逻辑**）；
3. 浏览器起不来 → **原样透出原因，不谈学习**（不起一个必死的任务）；
4. 等端口真的能连（最多 45 秒兜底）；
5. 走 `_study_one(...)` 起学习任务 —— 并发闸 / 全局日闸 / 错峰全都在里面，不绕过。

**两个入口**：

- 行内按钮：浏览器没开时，在「学习」旁边显示「**⚡ 一键**」
  （浏览器已开着就不显示 —— 那时「学习」本身已是一步到位，多一个按钮是噪音）；
- 批量动作：`start-and-study`，勾多个账号一次搞定。

**新接口**：`POST /api/study/start-with-browser`。

### 批量 `start-and-study` 的配额语义

复用 `start` 那一套：`room = 上限 - 在跑`，超出**入队**（P2b 队列），
全局日时长满了整批拒绝。

⚠ 已知代价：批量时**逐个等**浏览器（每账号最多 45 秒），N 个账号 = N×40 秒。
这是有意的：同时起 N 个 Chrome 会抢资源，且前端已提示「每个 10~40 秒、别重复点」。
