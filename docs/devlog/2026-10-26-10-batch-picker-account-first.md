# 2026-10-26-10 批次选课改为「先勾账号 → 课程按账号过滤」+ 学校可见

## 本次目标

用户看完上一版的课程选择器（按 pid 聚合 + "N 个账号有此课 · pid="）后提出四点疑问：

1. 有 pid，但仍不知道"这门课该选给哪些账号"；
2. 不同学校会不会混进来；
3. 有新账号加入后，怎么做选择才既方便又准确；
4. "N 个账号有此课"这个数会变（今天 2、明天 3），"再创建又是新一个任务，这样也不合理"；
5. 结论性追问："你这个选择是让我根据 PID 来选，对吗？我感觉这里面的选择还是不够明显，你觉得呢？"

## 结论与判断（读码 + 读库求证）

- **不会串校**：`platform_course_id` 是平台侧课程实例 ID，不同学校各自建的课 pid 不同 → 同名课会被拆成多项。**但界面看不出归属学校**，用户"看不出"是真实问题。
- 查库实证：`courses` 表只有 `课程名 / platform_course_id / clazz_id / url`，**没有学校**；学校在 `account_profiles.school`，而两个账号的 `school/dept/cls` **全为空**（只有 grade=2026）→ 界面上无料可显示。
- 隐患：上一版分组键**只含 pid，不含 clazz_id**。若两账号同 courseid 不同教学班会被合并。当前 9 个课程实例 pid↔clazz 均 1:1 未触发，属于潜在漏洞（本次改为显式提示"该课程ID跨校出现，请核对"而不擅自拆分——拆了运行端仍按 pid 匹配，会造成"选项不同、运行相同"的错觉）。
- **"N 会变"不是数据问题，是文案问题**：那个 N 只是"当前已抓课程里有多少账号有它"的参考值；批次锁死的是 `course_pid + 勾选的账号名单`，**新增账号不需要重建批次**，只需「编辑批次」把新账号勾上。原选项把 N 摆在主位，导致用户以为"数字变了=批次变了"。
- **顺序反了**：先选课、后选账号，而"这门课给哪个账号"本该先定人。

用户拍板：选课顺序 = **先勾账号、课程按账号过滤**；学校信息 = **等需要时每个账号只登一次、一次抓全，两号串行不并发、带随机间隔模拟人**（本次不改登录，只把学校字段显示能力备好）。

## 改动（全部在 `src/xxt/panel/app.py`）

1. **overview 下发画像**：`profile` 键从 `name/student_no/grade/major/term` 扩到含 `school/dept/cls`，课程下拉才有学校可标。
2. **批次弹窗重排**：`① 账号` → `② 课程`；课程 `<select>` 加宽到 520px；底部提示改为"批次锁定的是「平台课程ID + 你勾的账号」，以后新增账号不用重建批次，点「✎ 编辑」把新账号勾上即可"。
3. **课程下拉按账号过滤**（`courseMap` / `buildCourseOptions`）：
   - 未勾账号 → 列全部（便于先看有什么课），提示"① 先勾账号 → ② 课程列表只显示这些账号抓到的课"；
   - 已勾账号 → 只列这些账号有的课，选项文本 `《课程名》 · 学校 · 你选的 N/M 有`；
   - **去掉会变的全局"N 个账号有此课"**，pid 退到 `data-pid` 属性（不再占标题位）；
   - `courseSchool()`：画像 school 为空时显式写「学校未填」，不留白让人猜。
4. **覆盖核对改为主信息**（`updateCourseCov`）：缺课时列出**账号名**（`#2 乙同学`）而非只有 id；同一 pid 出现多所学校时追加"该课程ID跨校出现，请核对"。
5. **批次卡片缺课徽标**（`renderPlans` + `accountHasCourse`）：勾的账号里没有本批次课程（按 pid）时显示「N 个账号缺此课」，title 列出账号 id —— 直接回答"新账号进来怎么办"。
6. **编辑不丢 pid**：占位 option 带 `data-pid`，`doPlan` 优先取 `selectedOptions[0].dataset.pid`，避免保存时把 pid 洗成 null。
7. `accDesc()` 增加学校位（同名课跨校时先看这一位）。
