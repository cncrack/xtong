# 会话记录 2026-10-25-01 — Key 保存不生效根因修复 + AI 区块布局重构

## 本次目标

用户报：① Agnès 配置过多次仍显示"尚无可用 Key"、要反复配置；② AI 模型区块布局不好看。

## 结果

✅ 完成（9fdbfd1，测试 43/43，浏览器实测）：

1. **根因（三环相扣）**：
   - 首次配置时恰逢 providers_save bug 期（builtin_list NameError）→ 保存失败
   - 之后用户再点保存时 Key 框空（密码框不回显，合理以为已存）→ "空=不修改" → key_enc 永远不落库
   - **深层 bug**：providers_save 写 provider_name 用裸字符串（未 json.dumps）→ 配置覆盖层
     json.loads('Agnès') 抛异常被静默吞且**中断整个覆盖层循环** → provider_name 之后的
     llm.base_url/model/key_enc 全部读不到 → 即使存了也显示不生效
2. **修复**：写入侧统一 json.dumps；覆盖层改**单行容错**（坏值跳过不中断整体）；DB 坏行修正；
   经 API 把用户 Key 正式入库（此前从未成功落库）
3. **布局重构**：AI 区块改卡片式（浅灰底圆角分组）——厂商 chips 一行 + 参数 2×2 紧凑网格
   （名称/模型一行、URL/Key 通栏）+ 按钮行内联状态提示；"留空=沿用已存 Key"直接写进标签
4. **实测**：状态卡显示"当前使用：Agnès（api.agnes-ai.cn / agnes-2.5-flash）｜✓ Key 已加密保存，
   可直接使用"——**本进程无环境变量 Key 的前提下**（证明加密存储链路完整）

## 教训（连环坑的统一根因）
