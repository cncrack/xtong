# 2026-10-30-01 同步与开刷解耦：登录只同步课程名单，章节树按人点才抓（轻档）

## 本次目标与最终结果

**目标**：用户提出并定调一条交互逻辑——「登录时只抓课程名称，确定要刷哪门才抓那门的章节树」。本轮只做方案审查后的**轻档**实现（不动学习引擎的抓树路径）。

**结果**：✅ 全部落地，`pytest` **306 全绿**（新增 6 例）。尚未实机验证（需用户操作），尚未推送。

起因是上一轮（会话 70）之后用户追问三件事：① 每门课的「▶ 刷这门课」点了该不该自动抓树；② 「超过 8 门怎么办」「本地没树但这门课不需要刷，你补它干嘛」；③ 「为什么会消费额度」。审查中我先提出「登录时自动补齐章节树」，被用户第 ② 问否掉——**要不要刷一门课是人的业务决定，代码猜不得**（体育课/免修课抓了就是白付一次页面访问）。最终采纳用户的按需方案。

## 关键决策及理由

1. **先纠正一个我自己在上一轮说错的概念**：「消费」被我混成一句话讲，实际是三层——同步课程名单（1 次访问，不扣额度）/ 抓章节树（每门课 1 次导航，**不扣额度**，因为额度只数 `video-done`）/ 开刷（真播视频，扣当日额度）。澄清之后，"抓树"的成本只剩一次页面访问，"要不要抓"就变成纯粹的访问预算问题，不再是额度问题。

2. **同步与开刷解耦**（本轮的设计核心）：登录只负责"课程名单与平台一致"，章节树由人在课程行主动点「⬇ 抓章节」。好处是抓完先看到节数，刷不刷仍是人的决定；同时天然解决"不需要刷的课不该抓"——不点就零访问。

3. **挖出并堵掉一处现成的重复访问**：`probe_session`（`xxt status` 探测）与 `fetch_courses`（`xxt courses`）访问的是**同一个** `space_url`、听的是同一批响应（后者还多截获 `courselistdata`），是前者的严格超集，以前各跑一次 = 白导航一次。改为 `cmd_login` 成功后顺带同步课程名单，登录链路少一次真实访问，且课程当场入库。

4. **不做「面板/引擎里就地抓树」**（重档，已设计未执行）：`adapter.fetch_chapters` 用同步 Playwright 且自己 `launch` 浏览器，在异步面板/异步引擎里直接调就是 2026-10-25 事故同源的 sync/async 混用；而现成 `xxt chapters` 子进程已把「抓树 + 入库 + 对账 + 双护栏」跑通（#2 的 70/70 就是它跑出来的）。所以新端点只做一件事：`_spawn` 那条 CLI。省掉 `CHAPTERS_UPSERT` 下沉、共用建库编排、两引擎同源改造这一大块风险。

5. **文案分流必须带着诊断分类一起改**（否则会引入新故障）：`stop_reason` 从「无待学章节」拆成「未抓章节树…」与「本地 70/70 已全部完成…」。若不同步 `core/diagnose.py`：新文案含"章节树"会被 `structure` 规则先命中 → 判成「页面打不开」→ 属可挂起 → 守护退避后白重试；而「已全部完成」不含任何 `done` 关键词 → 落 `unknown` → 同样白重试。故新增 `notree` 类（置于 `structure` 之前，档位 `needs_you`，不可挂起）并给 `done` 补关键词「已全部完成」。

6. **无树的课不再显示 ▶**（防误操作）：与其点了被拒再解释，不如按钮本身只给「⬇ 抓章节」；`study_start` 的第二问仍保留（守护与「立即补跑」走同一接口，也要拦）。抓树的 `confirm` 弹窗明确写「不播放视频、不写看完一节，因此不占用今日额度」。

## 本轮踩到的两个坑（写下来防再犯）

- **Python 3.11 不允许 f-string 的表达式跨隐式拼接的字面量**：`f"{f'…，" f'…）' if x else ''}"` 直接 `SyntaxError`。改为先算 `hint` 变量再打印。IDE 的 lint 对我这处报了「字符串未终止」（误报），**`ast.parse` 才是裁判**。
- **面板端点里 `conn` 在 `finally` 关闭**：第二问最初写在 `finally` 之后，用的是已关闭连接（`pytest` 会当场炸，但静态检查不报）。新逻辑必须放进 `try` 块内。
