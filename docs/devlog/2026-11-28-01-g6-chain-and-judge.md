## 二、最有价值的两条实测结论

### ① 平台交卷为什么要调 `SubmitExam()`

交卷按钮 onclick 是 `SubmitExam()`，它内部有一串必要前置：

```
ForbitOperate=1 → stopclock() → SaveMode=1 → 写 LeftTime → PackAnswer() → frmExam.submit()
```

只调最后一步 → 服务端状态残缺 → `alert('试卷保存失败，请稍后再保存')`。

**帧分工**（实测 14684）：

| 帧 | 函数 |
|---|---|
| `ExamTmStepHeader` | **`SubmitExam`** ← 交卷入口 |
| `ExamTmStepDo` | `PackAnswer` / `frmExam` / `check_index` |

### ② 判断题的选项顺序陷阱

| 来源 | 顺序 |
|---|---|
| 判分页 | `<label>1、错</label><label>2、对</label>` → `[错, 对]` |
| 答题页 | radio「对(value=1)」「错(value=0)」→ `[对, 错]` |

**同一道题，两处顺序相反。** 严格按顺序比对 → 题库永远命中不了 →
AI 重新猜 → 第 2 题反复答错。

修：判断题按集合比（对/错只有两个，答案存 value 不靠下标）。
