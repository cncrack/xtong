# 2026-11-07-01 浏览器卡片布局定稿（三轮回工）

## 一、这一轮解决的问题

用户连着给了三轮反馈，每轮都是对上一轮的否定 —— 全部记下来，
因为**这类「挤一下按钮」的小事做了三次才对**，值得留个教训。

| 轮次 | 做法 | 用户反馈 |
|---|---|---|
| 初排（11-02） | 42px 标签 + 按钮 `flex:1 1 0` 均分 | 「这几个按钮要重新排列一下」 |
| 一改（11-06-08） | 组标题占整行 + 按钮 `flex:1 1 44%` 两列等宽 | 「按钮太大太宽，右侧本来空间就不大，还这么浪费」；「原来面板的一些路径什么都没有」 |
| **定稿（11-07-01）** | 组标题回到行首 38px + 按钮 `flex:0 0 auto` 按文字宽 | 「有了」 |

## 二、一改错在哪（要记住）

`flex:1 1 44%` 是**强行两列等宽**：

- `停止` 只有 2 个字，也占半行 → 大块空白；
- `复制命令` 被拉成整行 → 看着像主操作；
- 组标题独占整行 × 3 组 → 白白多出 3 行高度；
- 加上按钮变大，`#browser` 区被挤出可视范围（`max-height:52%`）→
  **用户以为「路径信息没有了」，其实只是被挤到滚动区外**。

**教训**：给窄侧栏排版时，"等宽"几乎总是错的 —— 应该让**内容决定宽度**。

## 三、定稿的具体做法

### CSS（`page.py`）

```css
.bgrp{display:flex;align-items:center;flex-wrap:wrap;gap:5px;margin:0 0 7px}
.bgrp-title{flex:0 0 38px;font-size:11px}          /* 行首小标签，不占整行 */
.bgrp-btn{flex:0 0 auto;max-width:100%;min-width:0;padding:4px 9px;
          font-size:12px;white-space:nowrap;text-overflow:ellipsis}
.bgrp-batch .bgrp-btn{font-size:11.5px;padding:4px 7px}   /* 批量行再小一级 */
.b-note:empty{display:none}                        /* 空提示完全不占位 */
@media (max-width:760px){ .bgrp-btn{flex:1 1 100%;min-height:38px} }
```

- `flex:0 0 auto` = 宽 = 文字宽 + padding，**不拉长也不压缩**；一行放不下才换行；
- 组标题固定 **38px**，让三行按钮左边缘对齐；
- `max-width:100%` + `min-width:0` 保证未来新增长文案不会撑破卡片。

### 额外修正：路径区被挤

`.split-side>#browser{max-height:52%}` → **68%**，账号详情保底从 180px 降到 150px。
这直接解决了「路径看不见」。

### 批量行四个按钮挤进一行

原来 4 个按钮放不下是因为文案太长。缩短后（含义靠 `title` 保留）：

| 原 | 新 |
|---|---|
| 全选待启动 | 全选 |
| 一键启动并学习 | 启动并学习 |
| 只启动浏览器 | 只启浏览器 |
| 批量停止 | 停止 |

实测：标题 38 + 4 个 gap(5×4) + 四个按钮（39/74/74/39）= **288px**，
最窄侧栏约 **315px** → 放得下。

### 「未选中」删掉

用户原话：「未选中是做什么，感觉没有用」。

- 没选中 → `textContent = ""` + `.b-note:empty{display:none}` → **整行不占高度**；
- 选中了 → 「**已选 N 个：甲、乙、丙（可在表格勾选调整）**」，最多列 5 个；
- 「全选」按钮在可见账号全都不可选（都在跑）时自动置灰。

**教训留档（下次给窄侧栏排版直接照这个来）**：

1. **内容定宽**（`flex:0 0 auto`），不要"等宽均分"；
2. 组标题用**行首小标签 + 固定宽度**，不要独占整行；
3. 空间紧张时**先砍文案、砍字号、砍内边距**，三样一起砍比只砍一样有效；
4. **空态提示不要常驻**（`:empty{display:none}`）；
5. 改完先确认**有没有把别的东西挤出可视区**（这次就挤掉了路径行）。
