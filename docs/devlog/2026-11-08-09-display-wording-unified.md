## 一、我上一轮错在哪

用户说的是**显示口径**，我一直在解释「两个账号内容不同是对的」（那是**数据**差异）。
两件事都被用户说中了，而且都是真问题：

### ① 待学区「看起来像两套逻辑」

**代码其实只有一套**：`todoRows = rows.filter(r => r.state !== "done")`（全文件仅此一处）。
甲同学显示 2 行、test 只显示 1 行，唯一原因是 test 缓存只有 1 个未完成节
（8 行缓存，见 devlog 08 的 Bug A）。

但用户要的**信息确实缺失**：界面上没有「待学总共几节、正在学第几节」。

### ② 账号表「课程」列的 `7/8 节` 有歧义

`sec.done + "/" + sec.total` 里的 `total` 是**这份缓存的行数**，不是课程总节数。
缓存不全时就成了 `7/8` —— 用户读成「这门课只有 8 节」，**完全合理**。

## 二、修法

| 位置 | 改成 |
|---|---|
| 待学区顶部标签行 | 新增 **`正在学第 N / M 节`**（N = 待学列表位置，M = 待学总数）；无 learning 行时不显示（不写「第 0 节」） |
| 待学区折叠标题 | **`共 M 节 · 还差 X 分钟 · 正在学第 N 节`** —— 折叠时也看得到 |
| 账号表课程列 | **`已学 X 节 / 共 Y 节`**（完整缓存）；缓存不全时 **`已学 X 节 · 总数未知`** + ⚠ 提示 |
| 顶部节数进度条 | 缓存不全时加注 **「缓存不全，总节数未知（点「刷新节列表」补全）」** |

**关键原则**：**绝不拿缓存行数冒充课程总节数**。缓存不全就明说「总数未知」，
而不是画一个 7/8 的满格进度条让人以为快学完了。

### 序号口径的选择

`learningNo` 取的是**该节在待学列表里的位置**（1 起），不是平台节号。
理由：用户要的是「还差 M 节里正在做第几个」这种进度感，
而不是「第 1298 号节」这种内部 ID。
