## 关键决策及理由

1. **两个口令对应两条完整流程**（不是只跑 git 那一步）：
   - "提交" = devlog/文档同步 → 自审 diff → pytest → **定向 add** → commit；
   - "推送" = 未提交改动先按"提交"收尾 → push_check 全绿 → push。
2. **定向 add 写成硬规则**：落地时主对话正在并行开发（src 多文件改动、courses.py/测试未提交），
   `git add -A` 会把并行会话的半成品卷进提交——快捷口令越自动，越要锁死这条。
3. **门禁不绿即停**：快捷口令加速的是确认环节，不豁免质量门禁；永不 force push。
