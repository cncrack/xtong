## 二、三件事必须分开看

### ① 真实差异（不是 bug，不能改）

两个账号是**不同学生**，同一门课（value=32）进度不同：

| 节 | 甲同学（default） | 乙同学（test） |
|---|---|---|
| 2.1 国家安全概述 | `done 62/60` | `learning 0/60`（正在学） |
| 课程进度 | 33/36 | 7 节已完成 + 1 节在学 |

→ 待学区内容不同**本来就是对的**。**没有**为了「看起来一样」去动数据。

### ② Bug A：test 的「8 节」不是课程总节数

**证据链**：

1. `data/logs/` 里**没有任何 `gxks-sections-test-*.log`** —— test 从没跑过「刷新节列表」；
2. `sections_test_32.json` 只有 **8 行**（1290~1298），而同一门课在甲同学那份是 **36 行**；
3. `run_gxks.py` 用 `find_section` **逐页找单节**、只回写它经手的节（L314/L533），
   **从不全量读列表**；
4. `gxks_sections.py --all` 才会写 `pager` 字段 —— test 的缓存 **`pager` 为 None**。

⇒ test 的缓存 = 「刷课脚本经手过的节」，**不是课程全量**。面板却按「7/8 节」显示，
用户会以为这门课只有 8 节、快学完了。

**修**（零平台请求、纯本地判据）：
- 后端 `_account_cards` 加 `sections_partial = bool(cached_rows) and not cached.get("pager")`
  —— 完整读列表必写 `pager`，逐节回写不写，**这是唯一可靠区分**；
- 前端在标签行显示 `⚠ 缓存不全，请刷新`（title 说明「点刷新节列表读完整列表」）。

### ③ Bug B：同一行「学习中 + 未解锁」自相矛盾

`practiceCell()` 只看 `practice_ready`：learning 行的 `practice_ready` 是 false
（平台要学完才解锁），于是显示「未解锁」，与旁边「学习中」并排像 bug。

**修**：learning 行改显示 **「学完解锁」** + title 说明。语义准确（不是永久不可做），
也不与「学习中」冲突；已解锁的节仍走 `practice_ready` → 「可做 #id」，未变的节仍「未解锁」。
