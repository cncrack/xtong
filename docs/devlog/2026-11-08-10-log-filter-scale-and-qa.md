## 一、两个真 bug（已修）

### 根因

1. `renderLogFilter()` **只在 `LOG_MODE === "merged"` 分支里被调用**（原 `page.py:3266`）
   → 切到「单账号」后下拉从不重绘，且 `sel.disabled = LOG_MODE !== "merged"`
   把它置灰 → 用户看到「全部账号灰色不能选」。
2. 单账号分支 `renderLogBox()` / `renderRunLog()` 用 `LABEL`（当前选中账号）挑任务，
   而切换账号只能靠**点账号表行**（`pick()` → `LABEL = label`）；
   日志区自己没有账号选择器 → 「第二个账号切不过去」。
3. 过滤下拉是普通 `<select>`，把全部账号平铺；100 账号 = 101 项，没考虑规模。

### 修法

| 项 | 改动 |
|---|---|
| `LOG_FILTER` 语义 | 两种模式都生效：merged = 过滤合并流；single = 决定看哪个账号 |
| 下拉渲染 | `renderLogFilter()` 移到 `renderRunLog` 的 merged 分支**之外**，两种模式都调 |
| 下拉状态 | **不再 disabled**；single 模式隐藏「全部账号」option（那是合并流入口，由 `#log-mode` 管） |
| 切换入口 | 新增 `setLogFilter(v)`：single 模式选账号即 `renderLogBox()`，不必点账号表行 |
| 规模 | 新增 `#log-filter-q` 搜索框，账号数 **>12** 时显示，按显示名/代号本地即时过滤（不引入虚拟滚动，T7/T8 仍排 >50 账号）；含 375px 断点 |
| SSE 增量 | `appendLogLines` 单账号分支重绘判据 `LABEL` → `LOG_FILTER \|\| LABEL`，否则选别的账号后新日志不刷新 |
| 模式切换 | `setLogMode()` 同步 `LOG_FILTER`：进 single 时默认跟随 LABEL，回 merged 时若等于 LABEL 则清空 |

**验收**：`test_gxks_log_filter_scale.py` 12 条；全量 `pytest` **1301 passed**；
`node --check` 通过；`push_check` PASS；`PAGE` 153741 → **155945**。

## 三、G-6 题型 / G-7 题库与共建共享（代码实据）

**G-6**：`allowed_types = "2"` 只放行单选；平台 13 种题型，遇多选/判断整卷拒填。
按 G-5 实跑结果逐个放开。

**G-7**：题库只有 2 答卷/6 题；`gxks_work.py` **只调 `lookup_answer` 查库，
没有任何写回题目/答案的代码** → 用户 10-29 确认的「学习过程中题目自动入库」**确实没接线**。

**共建共享已按用户设想设计**（实据）：

| 层次 | 设计 | 位置 |
|---|---|---|
| 题目全局共用 | `gx_q_items` 按 `platform_qid + fingerprint` 唯一，**不带账号/课程字段** | `schema_gxks.py:22-30` |
| 标准答案跨账号共享 | `lookup_answer` 只认 `standard_source='site'`（平台判分客观答案），注释明写「跟谁做的没关系，所以可以给别的账号用」 | `gxks_questions.py:215-220` |
| AI 答案不外借 | `ai` 来源是某账号推理结果，按 N3「题干可共用、答案仍按账号隔离」 | 同上 |
| 答卷按账号隔离 | `gx_q_papers` 的 `UNIQUE(account_label, exam_start_id)` | `schema_gxks.py:50` |

⇒ **一门课一个题库 ✅ 天然成立**（题目按内容去重，不绑账号/课程）；
**多账号同课共建共享 ✅ 已支持**；**一个账号多门课 ✅ 不冲突**（答卷才带 `course_id` 分类）。

**两处缺口**：`gx_q_papers.course_id` 目前存的是**平台课程名而非 value**（PLAN L467），
且自动入库没接线。建议跟 G-5 一起做（待用户点头）。
