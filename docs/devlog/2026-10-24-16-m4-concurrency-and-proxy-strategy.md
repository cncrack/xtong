## 关键决策及理由

1. **并发模型：多进程优先、async 备选**：
   - 代码核实：StudyRunner 接口已按账号参数化（state_path/conn/seed 注入），多账号无需改内部；
   - 多进程 = M2/M3 已验收同步代码零重写（async 重写等于全部行为重新验收）、进程级崩溃隔离、SQLite WAL 支持；
   - Playwright 同步 API 官方禁止跨线程 → 多线程方案不存在，只剩多进程/async 二选一；
   - 几十账号内瓶颈是 N 个浏览器内存而非进程开销 → 多进程够用，规模化再评估 async。
2. **代理策略：分层选型，4G 出口是"更好的方案"**：
   - ≤5 账号家宽直连（0 成本、最像真人）；5~15 加 1~2 张 4G 卡；15~50 多 4G 卡（每卡 5~8 账号）或按时长住宅代理；50+ 代理池；
   - 4G 核心优势：运营商 NAT IP 天然被大量真实学生共享（同 IP 多账号在移动出口属正常），基站切换 IP 微变也正常——宽容度高于家宽；
   - **同 IP 密度 3~8**：机房/学校机房场景本就同 IP 几十学生，风险信号是行为同步而非 IP 复用（错峰+随机化已覆盖）→ 不追求 IP 绝对唯一，成本大降；
   - 配套：accounts.proxy 端点抽象（本地端口/远程代理来源无关）、低频出口一致性自检（漂移熔断）、**禁按流量计费**（每账号每日数百 MB~1GB 视频流量，按 GB 计费成本爆炸）；
   - 机场节点定位次优过渡（国内、出口固定、用户少）。
