## 四、落地内容（9 项）

### 1. 守护热重载（`cli.py` 主循环）

每轮巡检在跨日重置之后、回读之前，`s = Settings()` 重读一次。**三道保护**：

1. `_db_readable()` 先探活数据库——`Settings.__init__` 会**吞掉** DB 异常并回退内置默认值（额度瞬间变回 240/60 会误判「今日已达成」），读不了就整轮跳过；
2. `s_new.db_path == s.db_path and s_new.data_dir == s.data_dir`——**数据目录变更拒绝应用**（运行中换库 = 把今天的记录拆到两个库），写一条 WARNING；
3. 任何异常都保留旧配置、守护不崩（`err_once` 去重，不刷屏）。

重读后同步重解包 `_auto_limits()` 与 `reopen_run_now`，并用 `_sched_sig()`（`[auto]/[quota]/[pace]` 三段的 JSON 指纹）比对——**真变了才写一条** `auto-reload` 日志，例如：

> 配置已重载：单日硬上限(次)、每日任务额度(个) → 本轮起按新值判断

### 2. 终态重算（`_recompute_terminal` + 纯函数 `_reopen_verdict`）

内存里维护 `terminal_kind: dict[int, str]`（`"done"` / `"hardstop"`），写入点 3 处、重启时用 `_terminal_kind()` 回放历史事件恢复。判定顺序即五道闸：

| # | 闸门 | 不通过时 |
|---|---|---|
| ① | 会话正在跑（`marker_process_alive`） | 跳过——**绝不开第二个**，跑着的按启动参数跑完 |
| ② | 今天在 `skipped` 里（手动停/未登录） | 跳过——手动停最高优先级，今日让位 |
| ③ | 今日发起次数 ≥ 单日硬上限 | 跳过——复用现有安全阀，**不新增计数器** |
| ④ | `auto-done` 按**当前**额度重判（`_local_quota_reached`） | 仍达标 → 纸条继续贴，不再白跑一次 |
| ⑤ | 其余（含 `auto-hardstop` 过了③） | **解除**：`auto-reopen` + `fired.discard` + 清 `noted`/`wait_noted`/`retry_after` |

解除后计划怎么排：
- `reopen_run_now = 关`（默认）→ `planned.pop()` 按原定时/学习窗口重排；
- `reopen_run_now = 开` → `planned[aid] = 当前时刻`，下一轮巡检（30 秒内）直接发起。

**状态漂移自愈**：每轮开头把「不在 `fired` 里却还标着终态」的项清掉，即使某处漏了 `pop` 也不会误解除。

### 3. 新增配置项 `auto.reopen_run_now`（默认 false）

只有 1 个开关。**没做的两个**（附理由）：

| 用户提的 | 我的处理 | 理由 |
|---|---|---|
| 面板保存后立刻重算（不等 30 秒） | **不做** | 面板与守护是单向轮询，要「立刻」得新建通知通道；30 秒延迟够用 |
| 优先级方向做成开关 | **不做** | 这是「定义」不是「激进/保守」，做成开关只会让人困惑该选哪个 |

### 4. Q43 优先级接线

守护侧 `rows.sort(key=lambda r: (-_prio(r["priority"]), r["id"]))`——**数字大 = 先跑**，同值按 id 升序。不改 SQL（面板卡片仍按 id 稳定排序，作用域隔离）。`_prio()` 对空/非法值兜底 1.0。

### 6. 配置页重排（5 组）

```
① 今日目标      每日时长额度 / 每日任务额度     ← 从「📚 学习与作业」搬来
② 安全阀        每日最多自动发起 / 单日硬上限
③ 失败后等多久  退避基数 / 随机浮动 / 退避封顶 / 开跑回读
④ 单节怎么处理  7 项（原样）
⑤ 自动解除与生效 解除后立刻开跑（开关，默认关）
```

每项说明统一格式：**「范围 · 默认 · 作用」**（`0~240，0=不限 · 默认 240 · 只算真播完的时长`）。

> 改完保存即生效：守护每 30 秒重读一次配置……**不用停调度**。例外：数据目录/数据库路径改了必须重启程序。

保存 toast 从「已保存（新会话生效）」改为「已保存（守护 30 秒内自动重载，不必重启）」。

## 七、复盘

1. **上一轮提的「mtime + 时间戳探测」是错的**——`app_config` 没有 `updated_ts` 列。改成「每轮直接 `Settings()` 重读」，成本 1~3ms，比任何探测都可靠。
2. **「立刻生效」必须说清作用域**——本轮把话讲成「守护 30 秒内换参数；跑着的会话一律不变」，用户才点头。凡提热重载，必须同时说「谁重读、谁不许变」。
3. **用户两次要求英文附中文**，本轮所有新代码注释、日志、面板文案一律中文优先，英文标识符只在日志小字和 `title` 里出现。
4. **`_recompute_terminal` 原本写成一个大闭包，无法测试**——抽出 `_reopen_verdict` 纯函数后 9 个用例才写得出来。判定逻辑与副作用分离，这个模式应继续用。
