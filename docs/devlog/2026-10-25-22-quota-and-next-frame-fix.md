# 会话记录 2026-10-25-22 — 实况监控发现三处缺陷并修复（额度失效 / 切节误判 / 日志不可分）

## 本次目标

用户启动 2 个账号实跑，要求 AI 通过日志等手段监控是否异常。结果发现并修复 3 个缺陷。

## 结果

✅ 3 项已修，测试 45 → 46 全绿，真实库额度实测恢复。

### 缺陷 1：全局额度被账号级 0 覆盖（安全红线失效）

- 现象：日志「当日剩余额度：0 分钟 / 不限 个」，但全局配置是 `quota.daily_minutes=240`、`daily_tasks=60`
- 根因：`core/accounts.py:effective_quota` 用 `if row["daily_max_minutes"] is not None:` 判断，而账号表这两列在面板"✎ 管理"保存后是 **0**（新建账号才是 NULL）→ 0 被当成显式覆盖值，把全局 240/60 覆盖成"不限"
- 与面板文案矛盾：UI 明确写「0=用全局默认」（`panel/app.py`）
- 修复：改为真值判断 `if row["daily_max_minutes"]:`，0 即跟随全局
- 实测：库里两个账号现在都是 240 分钟 / 60 个

### 缺陷 2：账号#2 视频 0 个提前结束（切节按钮误判）

- 现象：21:22:17 `session-end｜下一节按钮不可点（可能已到课程末尾）｜视频 0 个`，而同章节的账号#1 正常播放
- 证据链（时间戳可反推）：
  - 21:22:08.850 跳过非视频任务点（第 2 次）
  - 21:22:17.181 结束 → 间隔 **8.3 秒 ≈ click timeout 8 秒**
  - 若是重新 find 会等 10 秒、若是找视频会等 25 秒，均不符 → 确定是**复用了缓存的旧 frame**
- 根因：`next_frame` 只在首轮查找并缓存；切换任务点/章节后 iframe 重建，旧 frame 必然 detached → `click` 抛超时 → 被误判为"已到课程末尾"直接结束
- 放大因素：pending 章节入口选中的是「2.12 作业」（非视频点），要先跳过两次才到视频，增加了 frame 失效概率
- 修复（`astudy.py` + 同步版 `study.py`）：每轮重新定位 next frame；click 失败时重取重试一次，**两次都失败才判定真不可点**

### 缺陷 3：并发日志无法区分账号

- 现象：两个号同时跑，过程日志（进入知识点/开始播放/进度/跳过）无账号标识，只能靠时间戳推断，诊断成本极高
- 修复：`astudy.py` 关键 9 处日志加 `[#账号id]` 前缀；额度行同时修显示歧义（`0` → 「不限」）
