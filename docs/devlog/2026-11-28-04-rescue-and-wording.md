## 二、兜底方案：抓失败不用重做

### 为什么需要

原流程：交卷 → 立刻抓判分页 → 抓不到 = 放弃，建议用户重做。
但判分记录是**永久的**，事后随时能补。

### 新函数 `practice.parse_review_standalone()`

`parse_review_online` 要 `raw_rows`（答题帧的题行）做逐题核对；事后补抓拿不到。
所以新写一个**完全从判分页 DOM 推断**的解析器：

| 项 | 从哪来 |
|---|---|
| 题干 | `div#ddTm_N > dl > dt`（去题号、去末尾 `(N分)`）|
| 选项 | `div#ddTm_N > dl > dd > label`（去 `A、`／`1、` 前缀）|
| 题型 | 恰好 2 个且为「对/错」→ 判断(4)；否则按单选(2) |
| 答案 | `span.tmda` 标的「标准答案」「考生答案」「考生得分」|

**校验（没有 raw_rows，靠这三条）**：
① 每题有 `dt` 且至少 2 个选项；
② 逐题满分合计 == 试卷总分；③ 逐题得分合计 == 总得分。

### 新脚本 `scripts/gxks_rescue.py`

```
--exercise-id ID   补某节
--all-missing      补所有「平台有、本地缺」的
--dry-run          只列不入库
```

走 ``成绩分析 → 选课后练习 → 读表拿 Clerk_Kscj_Id → 拼 URL → 抓 → 解析 → 入库``，
按 `(exercise_id, exam_start_id)` 查重。

### 实测验证（真实判分页）

用落盘的 `stage_2_1/exam_html/viewExam.html`（单选题 3 题）：
```
✅ 题数 3  得分 100.0/100.0
  #1 type=2 std=['b']  #2 type=2 std=['a']  #3 type=2 std=['d']
```

用浏览器上 1.6 的判分页也验证了判断题推断（`type=4`，分值 33/34/33=100）。

### ⚠ 边界（必须知道）

- **只补已交卷的**：成绩分析交卷后才有记录（历史 `gaoxiaokaoshi.md` §2.11 第 14 条）
- **没交卷就断了** → 兜底救不了，只能重做

## 三、关于「第一次就 100% 正确」——诚实结论

### 实测正确率（题库里的真实数据）

| 练习 | 结果 |
|---|---|
| 1.1 / 1.2 / 1.3 / 1.4 / 1.5 / 2.1 | 各 3/3 ✅ |
| **1.6（前两次）** | **2/3 ❌** |

**合计 24 题，对 22，错 2 → 91.7%**

唯一答错的题：`2025年是人民海军成立75周年。`
平台标准 = **错**（1949+75=2024），AI 却答「对」——它的 reasoning 明明写着
「2024 年为 75 周年，题目表述有误」，**自己算出不对，还是替题目圆场了**。

### ✅ 题库闭环已被真实验证

**1.6 第三次作答（2026-11-28 17:05）**：
```
题库命中 3 / AI 0
第1题 标准=对 我们答=对 ✅ 33分
```

**从 66 分到 100 分，靠的就是「第一次交卷把平台标准答案入库」。**

## 四、顺带纠正一句误导文案

日志原来打印：
```
待确认清单：3 题暂无待确认项（可能已核验过）
```

**「可能」让人没法判断**。实测（1.6 第三次）：题库命中 3/3、判分全对，
`gx_pending` 里压根没有新的待确认行——**这是正常且最好的结果**。

改为：
```
待确认清单：本次 3 题均用平台标准答案判定，无需人工确认
```
