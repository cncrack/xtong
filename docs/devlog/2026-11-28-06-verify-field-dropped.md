## 一、现象

- 面板「二次验证」列**全部空白**

## 二、排查过程（关键：先证明验证器本身没坏）

直接用真实配置实测 `_make_verifier`：

```
_make_verifier 构造成功
验证结果: {'keys': ['a'], 'agree': False, 'confidence': 0.9,
           'reason': 'VT-4未配备无人机，属臆测信息'}
```

**验证器工作正常**，而且真抓到了第 1 题的分歧（我们答「对」，它认为「错」）。

所以问题不在验证器，在**数据传递链路**。

## 三、根因

`plan_answers()` 算好了 `verify` 并放进每个 plan item，
但 `gxks_work.py` 组装 `result["questions"]` 时**没搬这个字段**：

```python
# 改前（verify 在这里被丢掉）
items = [{"ordinal": p["ordinal"], ..., "reason": p["reason"]} for p in plan]
```

## 四、修法

```python
items = [{..., "reason": p["reason"],
          **({"verify": p["verify"]} if "verify" in p else {})}
         for p in plan]
```

用 `**({...} if ... else {})` 而不是直接 `p["verify"]`，是为了**向后兼容**：
题库命中的题、`--no-verify` 时本来就没有这个字段，不能因此 KeyError。

## 五、一个值得记住的信号

1.7 第 1 题：`VT-4坦克配备有无人机。`

- 我们（第一遍）答：**对**
- 二次验证：**不同意**，理由「VT-4 未配备无人机，属臆测信息」
- **平台标准答案：对** ← 我们对了，二次验证错了

**这印证了 11-28-05 定的规则②：不一致时绝不自动改答案。**
如果当时设计了「以审核者为准」，这题就会被改错、丢 33 分。

同时也说明：二次验证的价值是**提示复核**，不是替代判断。
