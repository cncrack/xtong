## 一、「设 4 节跑了 5 节」= 口径混淆，不是超刷（G-13）

### 事实

日志 `gxks-study-test-20261108-140309.log`：

```
=== 连续播放开始 14:03:12（最多 4 节 / 10.0 小时）===   ← 本次上限，确实只播 4 节
  ----- 第 1 节 1293 → 第 2 节 1295 → 第 3 节 1296 → 第 4 节 1297 -----
今日累计：5 节 / 153 分钟（额度 10 节 / 600 分钟）      ← 5 = 本次 4 + 凌晨 1
```

账本 `data/gxks_ledger.jsonl`（test / 2026-11-08）5 条：
`00:27:43 → 1292`、`14:45:54 → 1293`、`15:08:43 → 1295`、`15:31:34 → 1296`、`16:02:08 → 1297`。
**00:27 那节是 11-07 深夜那轮跨零点记到今天的。**

### 结论

- 截图里的「4」= `--max-sections`（**本次**最多播几节），本次严格只播 4 节；
- 「今日 5/10」= 日额度口径（凌晨 1 + 本次 4），`10` 是账号 `daily_sections`；
- 「近24h 7 节」= 滚动 24 小时窗口（含 11-07 白天）。

**三个数字口径不同，都不是 bug。** 但两个数字都长成一个输入框 → 用户混了，这是 UI 缺陷。

### 修（P-3 / G-13，已落地）

| 位置 | 改动 |
|---|---|
| 账号行输入框 | 前面加「本次」小字前缀（`.sec-n-lab`，11px 灰）；`title` 写明「与每日额度无关」 |
| 「学习」按钮 | `title` 补「每日总量受『每日额度』限制（在 ✎ 编辑里）」 |
| 编辑弹窗 | `日节数上限` → **`每日额度（节）`**；`日时长上限` → **`每日额度（分钟）`**；hint 加一句与「本次」的区别 |
| CSS | `.sec-n-lab` 含 `≤760px` 断点（375px 约定） |

`PAGE` 144108 → **144785**；`pytest -k "gxks_panel or gxks_sections"` **200 全绿**。

## 二、「两个账号待学区不一样」= 设计如此，但需求缺口真实存在（G-11）

### 用户问的三件事，逐条答

**Q1「是不是前面有改过代码导致显示不同？」**

不是。查 `git log -- page.py`：最近 8 个提交无一处动 `renderSections` 的账号维度。
`renderSections(state)` 自 11-03 起一直是**单账号渲染**：只读 `state.sections`（当前选中账号 + 当前课程的那一份缓存）。切账号才换内容。

**Q2「规划是按什么形式显示的？每个账号是不是该显示一样的？」**

规划原文（devlog `2026-11-08-01` §三 核心原则）：

> **「账号 × 课程」是二维的；列表永远是唯一全量视图；详情一次只看一个 (账号, 课程) 组合。**
> ```
> 账号表（唯一全量视图）→ 点某账号 → 详情区按 (账号, 课程) 切换
>   ├─ 进度：默认「只看在跑的迷你卡」(账号·课程·节·x/y)
>   └─ 点「展开」才按需加载完整节列表
> ```

**所以「每个账号显示一样的节列表」不是目标**——目标是「账号表一屏看全，详情按需点开一个」。两个账号待学区不同是**正确的**（甲的课还剩 3 节、乙的课 7/7 全学完）。

**Q3「这个学习进度表有没有实现？」**

- **账号表（全量视图）**：✅ 已实现（含今日节数/分钟、课程 done/total、登录、操作）
- **行内迷你进度条**：✅ 已实现（`miniBar()`，今日 x/上限）
- **「只看在跑的迷你卡」T6**：❌ **未实现**，一直是待办
- **多账号节列表并排**：❌ **未实现，且按设计不该做**（100 账号会爆）

### 现场差异的真实成因（G-12）

两个账号连缓存文件形态都不一样：

| | 甲同学（default） | 乙同学（test） |
|---|---|---|
| 文件 | `sections_default.json`（**无 course 后缀，legacy**） | `sections_test_32.json` |
| `course` | `""` | `"32"` |
| `pager` | `{current:6,total:6,...}`（旧版 `gxks_sections` 写的，**现 app.py 已不产出**） | 无 |
| 行数 | 36（33 done + 3 待学） | 7（全 done） |
| `read_at` | `2026-11-08 18:39:29` | 本地回写 11-07 22:41 / 11-08 16:02 |

甲同学的文件是 11-03「按课程分文件」之前的旧格式，之后再没重读过 → 停在 `course=""`。
**点一次「刷新节列表」即自动迁移成新格式**，不需要改代码。

### 决策缺口（要用户拍板）

| 选项 | 内容 | 代价 |
|---|---|---|
| ① 保持现状 | 单账号详情，切账号看 | 符合设计；但「一屏看多账号学到哪」做不到 |
| ② **落 T6 迷你卡**（建议） | 账号表行内直接显示「正在学第几节 x/y」+ 进度条 | 改动集中在一行渲染，不动详情区；对 100 账号友好 |
| ③ 做多账号进度总表 | 一屏并列所有账号节列表 | **与设计原则冲突**，100 账号必爆，不建议 |
