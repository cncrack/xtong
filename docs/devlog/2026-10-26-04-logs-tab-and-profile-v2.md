## 二、关键决策及理由

1. **日志独立成页，而不是只挂在账号页**
   日志是全局时间线（跨账号、跨批次），挂在任何单页都语义不对；固定在页尾时统计页被挤掉半个屏幕，且"展开更多"控件埋在底部没人用。独立后可以加账号筛选和 20/50/100/300 条档位。

2. **勾选状态与筛选分离**
   典型坑：`doPlan()` 原来用 `querySelectorAll('#pl_accs input:checked')`，一旦加搜索，筛掉的账号其 checkbox 就从 DOM 消失 → **已选的人被静默丢掉**。改为 `PLSEL: Set<number>`，渲染只是投影。

3. **「只看未排」默认勾选**
   同一账号只能在一个启用批次里（后端 `busy_accounts()` 拒绝），所以已排账号默认隐藏，避免用户点了才被拒。

4. **按课程聚合只统计视频**
   `work-start` 的详情是 `作业名｜模式`，**不含课程名**。硬取首段会冒出「2.12」这种伪课程（本次实况数据里就出现了）。所以在 `by == "course"` 时直接跳过非 `video-done` 行，宁可 works=0 也不编；UI 上标注"按课程聚合只统计视频（作业日志里没有课程名）"。

5. **学号独立成列，不塞进 `note`**
   塞 note 就没法结构化展示/检索，且备注是用户自由文本。加列 + `source`（`manual`/`platform`）为将来"从平台读取画像"留位。

6. **趋势与筛选同源**
   `trend` 在同一个聚合循环里累加，所以"按年级 + 关键字"的筛选会同时作用于条形图和趋势柱，不会出现"表里 2 个号、图上 5 个号"。

## 五、给用户的三个解释（本轮问答，落档备查）

1. **「未标注」是什么**：不是预备分类，是**兜底桶**——账号没填画像时其所有刷课记录归到这里。填了画像就不存在这个桶；所以它本身也在提醒"还有账号没建档"。已加角标与一键跳转。
2. **年级/专业/学期平台有没有**：**需要实测确认，不能凭空断言**。按公开信息，学习通个人中心常见的是**姓名 / 学校 / 学号 / 院系（有时有班级名）**；"年级"通常要由学号或入学年份推断，"专业/学期"多属教务系统数据，学习通一般不给。因此本轮只做"手填 + 学号/姓名展示"，**未擅自加平台抓取**（会多一次平台访问，违反最小访问原则，等你点头再做）。
3. **统计关键字搜索**：已支持，且是服务端过滤（不是前端假筛），所以合计行/趋势柱也随关键字变化。

## 六、遗留与风险

1. **"从平台读取画像"未做**：可做成一键按钮（用已存 `state.json` 打开个人中心，尽力抓 姓名/学校/学号，抓不到就留空），前提是用户同意一次实况访问；年级/专业/学期大概率仍要手填。
2. **日志页未做"按事件类型筛选"**（video-done / session-* / work-*）：现在只有账号维度，事件类型多起来再补。
3. **趋势柱状图无坐标轴与数值标注**（悬停 tooltip 里有），如果后面要看更细可换折线 + 周日汇总。
4. **`by=course` 时 works 恒为 0**：这是刻意的（作业日志无课程名），已写进 UI 脚注，避免被当成 bug。
