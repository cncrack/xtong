## 关键决策及理由

### 决策 1：`stalled` 从「干等」改为「重载恢复」

**实测时间线**（1305「3.2 外国军事思想」，视频 3011 秒 = 50.2 分钟）：

| 时刻 | 平台学时 | 事件 |
|---|---|---|
| 01:30:36 | 36/48 | 正常，1:1 记账 |
| **01:33:57** | — | **`stalled` 视频卡住** |
| 01:36:06 | 39/48 | 之后**再也不涨** |
| 01:45:43 | 39/48 | 视频播完 |

**视频播了 50.2 分钟，平台只记 39 分钟 → 差 9 分钟永远补不回来 → 整节作废，60 分钟白跑。**

`plan_action("stalled")` 原来返回 `"wait"`（干等）。干等没用，因为：
1. 卡住时**画面不推进**；
2. 平台按**墙钟**计时（`m_time` 每秒 +1），不看 `currentTime`；
3. ⇒ 那段时间服务端**不记账**（与 Q13「媒体重建后服务端停止记账」同源）。

**修法**：`stalled` 与 `rebuild` 共用「重载播放页开新会话」路径，带
`RELOAD_COOLDOWN_SECONDS` 冷却与 `MAX_RECOVERIES_PER_SECTION` 次数上限。

> ⚠ **为什么前几天没暴露**：历史上从未出现过 `stalled`（11-02 三次任务 + 11-03
> 两次任务共 5 次跑，`stalled` 计数全为 0）。1305 是迄今最长的一节（50.2 分钟），
> 第一次触发。这是**潜伏很久的 bug**（从 10-29 就这样写），不是新引入的。

### 决策 2（**重要教训**）：绝不篡改 `currentTime`

**我犯的错误**：为让学时涨，在 `play()` 里加 `v.currentTime = 0`（结尾回卷）。

**这违反了 `docs/PLAN.md` §8 的硬性约定**：

> 真实播放：由平台播放器自然播放、自然上报进度心跳；**绝不跳帧/篡改 `currentTime`**
> （学习通可检测跳秒）

**引发的连锁反应**：
1. 回卷后下一拍 `t` 从 ~2900 掉到 0；
2. 正中 `classify()` 的「倒退 = 重建」判定 → `reload_player()`；
3. 重载后又回卷 → 又判重建 → **死循环**；
4. 日志表现：`rebuild` 连刷、`m_time` 一直只有几秒、学时 43/48 不动。

我甚至一度想去改 `classify()` 给它开「回卷豁免」—— **那是掩盖症状，更错**。

**已全部回滚**：`play()` 只调 `play()`；`classify()` 的「倒退即重建」恢复原样；
删掉了基于错误前提写的 `test_gxks_rewind_not_rebuild.py`。

**教训**：「让学时上涨」永远不能靠改播放位置。恢复手段只有「重载开新会话」。

### 决策 3：节列表 `_gather` 必须**显式回到第 1 页**

**现象**：刷新节列表后 `summary {sections: 27, done: 8}`，缺了 1289~1297 共 9 节
（其中 1.1~1.9 全是「已完成」，所以「已完成」从 16 掉到 8，看起来像数据错了）。

**根因**：

```python
start = pager.get("current")     # 实测是 4（上次刷课停在最后一页）
last  = pager.get("total")       # 4
page  = start                    # 4
while True:
    drv.read_page()              # ⚠ 内部点 #btnSearch 触发 ASP.NET 回发
    if page >= last: break       # 回发把页码重置回 1，但本地 page 还是 4 → 4>=4 立刻退出
```

**修法**：先 `goto_page(1)`（双向翻页已在 `-01` 补齐），每轮以**读回的分页器**为准，
不信本地累加的 `page`。实测**读全 36 节** ✅

### 决策 4：日志**倒序显示**（最新在最上面）

**用户原话**：

> 「日志没有把最新的那一每次显示在上面，如果我要看以往日志，我可以鼠标往上滚」
> 「日志的记录每4秒刷一下就跳一下，记录就回到最上面了」

**我之前方向搞反了**：实现成「正序 + 自动滚到底部」。后果：
- 正序时最新行在**最下面**，容器一限高就必须滚到底才看得见；
- 每 4 秒重绘 `innerHTML` 会重置滚动位置 → 表现为「一直跳」。

**改法**：把 `tail` **倒序渲染**（`tail.slice().reverse()`）+ 重绘后 `scrollTop = 0`：
- 不用滚，最新行永远在视野第一行；
- 4 秒重绘后回到顶部 = 回到最新，**不会跳**；
- 要看历史就自己**往下滚**（倒序里「更早」在下方）；
- 用户已往下滚时还原位置，不抢滚动。

顶部加一行小字：「↓ 最新在上；要看更早的日志请往下滚」。
