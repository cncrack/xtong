### 2.1 账号卡片总览（后端）

`panel_gxks/app.py` 新增 `_ledger_path()` / `_account_cards()`，`/api/state` 增 `cards` 字段。
**只读本地**，不发任何平台请求（最小访问原则）：

| 卡上信息 | 数据来源 |
|---|---|
| 显示名 / 代号 / 端口 / 是否停用 | `accounts.local.json` |
| 今日已学节数与分钟、今日剩余节数 | `data/gxks_ledger.jsonl`（`ledger.today_totals`，按账号） |

| 课程名 / 节进度 done/total / 读于 | `data/debug/sections_<代号>.json` 缓存 |
| 是否运行中 | `_JOBS` 内存表 |

两个刻意选择：

- **凭据只回布尔**：用 `acc.configured`（账号表自己的 name/pw）而不是旧全局 `account.local.json`，
  否则多账号下所有卡都会假“已配置”；回包只给 `true/false`，值一个字节都不出。
- **额度左侧不为负**：`left = max(0, daily_sections - today["sections"])`。

### 2.2 账号卡片总览（前端）

- `.acct` 卡片：头部（显示名 + 状态标签 + 代号@端口）、四行键值（今日/端口/登录/课程）、底部动作位；
- 整卡 `onclick="pick(label)"` 切账号；卡内按钮包一层 `onclick="event.stopPropagation()"`，
  否则「点停止」会顺手切账号；
- 动作位按状态给**一个**按钮，不做一排灰按钮：运行中→「停止」/ 停用→「已停用」/
  浏览器没开→「浏览器没开」/ 额度用完→「额度已用完」/ 否则→「开始学习（n 节）」（n=min(3, 剩余)）；
- `pick()` 里 `SEC_SIG = ""` 强制重建节进度——两个账号的数据签名（读于时刻+行数+完成数）可能撞车；
- `renderSections` 的标题改为「显示名 · 课程 · 读于」，`SEC_SIG` 加入 `state.label`。

### 2.3 多账号排列规则（回答用户提问）

`.cards` 用 CSS Grid 自适应列：

```css
.cards{display:grid;grid-template-columns:repeat(auto-fit,minmax(300px,1fr));gap:14px}
```

- 列数由**容器宽度**决定，`main` 最宽 1280px（内容宽约 1244px）→ **最多 4 列**（每列约 300px）；
- 实际列数 = min(账号数, 能放下的列数)：1 个账号→整行 1 张；2 个→各半；3 个→三等分；5 个→4+1 换行；
- 顺序 = `accounts.local.json` 里的顺序，从左到右、从上到下；
- **为什么改 `auto-fit`**：原先是 `auto-fill`，账号少时会留下空轨道，1 个账号只占约 1/3 宽、
  右侧空一大片（实测），改成 `auto-fit` 后空轨道被折叠，卡片撑满。
- 窄屏（<632px）自动降为 1 列，不需要媒体查询。

## 三、关键决策及理由

1. **卡片数据只读本地，不发平台请求**：4 秒轮询 × N 个账号，若每轮去平台取进度就是持续访问；
   节进度沿用现有 `sections_*.json` 缓存，卡上标明「读于 时间」，旧数据不冒充新数据。
2. **额度口径沿用账本，不新开门径**：`ledger.today_totals` 既有行为是**节数去重、分钟按实际累加**
   （`test_gxks_ledger.py` 已锁定 186.0 那条语义），本次不改账本，只在展示层 clamp 到 0 以上。
3. **一行只给一个按钮，把“为什么点不了”放进 title**：卡片是总览，不是控制台；
   状态塞进 disabled 按钮（「浏览器没开」）比给一排灰按钮更容易扫读。
4. **`auto-fit` 而非 `auto-fill`**：见 2.3，这是本次“丑”的主因之一。
5. **字号只上调一档，不引入字体文件**：单文件 exe 不能带 web font，仍用系统
   `-apple-system / Segoe UI / Microsoft YaHei` 栈。
