## 二、晚上那个真 bug（`-06`）的关键

用户报「林鑫阳登不上」。操作记录：

```
22:37:22 | (批量) | error | default=等了 40 秒，端口 9222 未响应
```

但脚本 `22:37:09` 写 `ok:true pid=27024`，之后 27024 已死。

**根因**：`chrome.exe` 是**启动器**。`Start-Process -PassThru` 拿到它后，它建 profile 锁、把工作交接给新进程、自己退出 → `$proc.Id` 变死 pid。面板拿死 pid 判「是否在运行」/「停止」全错。

**这也解释了上午 test03 的「报 ok 但窗口没了」**——当时归因为"用户关了窗口"，其实是同一个 pid 失效问题。

修法（方案 A+B）：
- A：脚本写 result 前用 `Get-NetTCPConnection` 查 OwningProcess
- B：面板 `_await_chrome_ready` 调新增 `gchrome.port_owner_pid()`（netstat 查 LISTENING）兜底

**顺带**：编辑时 `start_chrome.ps1` 丢了 BOM，已用 `UTF8Encoding($true)` 补回。**以后编辑 .ps1 要查 BOM。**
