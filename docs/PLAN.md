## 1. 背景与目标

构建一个自动化网课学习助手：

1. 模拟登录目标学习网站；
2. 自动进入课程并"学习"视频内容；
3. 视频播放过程中弹出题目时，自动识别题目并调用 AI 作答、提交（**计分项，功能后置**）；
4. 记录学习进度与作答结果。

**目标平台（已确认）：超星学习通，采用学习通账号密码直接登录**（非学校统一认证入口）。

**演进路线（v0.2 调整为四阶段，弹题按用户要求后置）：**

| 阶段 | 内容 | 说明 |
|------|------|------|
| P0 | 单用户视频学习闭环 | 一个学习通账号：登录→课程发现→自动刷视频 |
| P1 | 多账号统一管理 | 账号池加密存储、**多账号同时学习**（并发可配置）、管理面板 |
| P2 | 弹题 AI 作答 | 弹题**计分**，AI 识别作答；配置开关默认关闭，题库+半自动校准先行 |
| P3 | 代码加密保护 | 核心代码混淆/编译、授权机制、打包分发 |

> 仍保留"平台适配层"设计：学习通作为第一个适配器，平台相关细节全部收敛在
> `src/xxt/adapters/` 内，未来可扩展其他平台（智慧树、雨课堂等）。

## 2. 需求分解

### P0 — 单用户视频学习闭环

- [ ] 账号登录：学习通**账号密码直接登录**；首次有头浏览器人工辅助（处理验证码），保存会话（storage_state），后续免登录自动恢复
- [ ] 会话管理：有效性探测；因持有账号密码，cookie 失效可**自动重登**（遇验证码再转人工介入）
- [ ] 课程发现：抓取课程列表 → 章节树 → 任务点（视频/测验），落库
- [ ] 视频学习：逐任务点自动播放（静音、适当倍速），播完自动跳下一节
- [ ] 可观测：本地运行日志 + 进度记录（SQLite）

### P1 — 多账号统一管理（已确认需求）

- [ ] 账号池：多账号（账号密码、cookie）加密存储，用户自己统一管理（增删/启停）
- [ ] 并发学习：**多账号同时学习课程**，全局并发数可配置；每账号独立会话隔离
- [ ] 额度与退避：每账号**双额度**（每日时长 + 每日任务数）任一达标即停、完成量上限内随机浮动、失败指数退避
- [ ] 账号级作息：每账号可设学习窗口/计划开始时间（基准 + 随机抖动），未设置用全局默认；调度器支持账号间自动错峰
- [ ] 课程轮换与优先级：优先级**按账号×课程**设置（courses 表 `priority`），未完成度程序自动计算；加权随机轮换、每日多门穿插（1~3 门随机）；**同一时刻单任务点为硬约束，程序内绝不给同账号多开**
- [ ] 章节级选点：默认顺序推进；可配置**章节优先级**（chapters 表 `priority`）与低概率随机跳章（拟人化，每日 ≤1~2 次）；实现前须完成三项平台核实（乱序计分 / 章节锁定 / 跳章后"下一节"行为）
- [ ] 代理与出口管理（v0.12 方案先行、按需落地）：分层选型（家宽直连 / 4G 卡 / 按时长住宅代理）、同 IP 密度 3~8、accounts.proxy 端点抽象、出口一致性自检
- [ ] 管理面板：账号管理、进度看板、日志查看、暂停/恢复

### P2 — 弹题 AI 作答（计分项，后置实现）

- [ ] 配置开关 `quiz.enabled`，默认 `false`；关闭时弹题按平台默认行为处理（不干扰视频流程）
- [ ] 弹题检测：DOM 监听识别题目弹层；图片/canvas 题走 OCR 兜底
- [ ] 解析题型：单选/多选/判断/填空 + 题干 + 选项
- [ ] 作答管线：本地题库优先 → LLM（配置化）兜底 → 低置信度标记待人工
- [ ] **半自动模式先行**（AI 填入建议答案、人工确认），校准正确率后再开全自动——弹题计分，正确率要求高
- [ ] 判题结果回写题库：答对入库复用，答错记录并支持换答案重试

### P3 — 代码保护

- [ ] 核心模块加密（混淆/编译），源码不可逆
- [ ] 授权机制：机器码绑定 + 激活码 / 到期时间
- [ ] 打包为可执行文件（exe），免 Python 环境运行

## 3. 总体架构

```
┌────────────────────────────────────────────┐
│ 管理端：CLI（P0） ──→ Web 管理面板（P1）      │
├────────────────────────────────────────────┤
│ 任务编排层：调度器 / 任务队列 / 章节状态机      │
├────────────┬─────────────┬─────────────────┤
│ 平台适配层   │  AI 答题服务  │  账号与会话管理    │
│ (学习通适配器 │  (LLM 调用 +  │  (登录/cookie/   │
│  可扩展多平台)│   题库缓存)   │   验证码/自动重登) │
├────────────┴─────────────┴─────────────────┤
│ 执行层：Playwright 编排 + 页内注入 watcher      │
├────────────────────────────────────────────┤
│ 存储层：SQLite（账号/课程/进度/题库/日志）      │
└────────────────────────────────────────────┘
```

设计原则：

- **适配层隔离**：所有与学习通相关的选择器、URL、接口封装在 adapter 内，平台改版只改 adapter；选择器配置化（存于配置文件而非硬编码）
- **引擎与执行分离**：任务编排是纯逻辑状态机，可单测；浏览器操作全部下沉到执行层
- **AI 可替换**：LLM 走 OpenAI 兼容接口，provider/模型/端点全部配置化，免改码切换
- **部署形态无关**：所有数据路径相对 `data/`，无硬编码绝对路径，Windows 常驻与 Docker 容器同一套代码
- **混合执行架构**：外层 Playwright 负责"编排与决策"（登录、进课、切节节奏、异常恢复），页内注入 watcher 负责"细粒度执行"（视频定位/保活/事件上报），两者以事件桥通信；页内 watcher 复用开源项目 xuexitongScript 的成熟经验重构（见 §5.8）

## 4. 技术选型

| 项 | 选择 | 理由 | 备选 |
|----|------|------|------|
| 语言 | Python 3.11+ | 生态成熟、AI/自动化库齐全 | Node.js |
| 浏览器自动化 | Playwright | 官方维护、多 BrowserContext 天然支持多账号隔离、CDP 能力全 | DrissionPage（国内对抗经验丰富，遇到风控时可切换）、Selenium |
| LLM 接入 | OpenAI 兼容接口（httpx），**完全配置化** | base_url/model/api_key 均在配置中，GLM/DeepSeek/Qwen/本地 Ollama 随时切换，不改代码 | — |
| 后端/面板 | FastAPI（P1） | 轻、异步、自带文档 | — |
| 存储 | SQLite（WAL 模式） | 单文件零运维，几十账号规模够用 | MySQL（规模大时） |
| OCR 兜底 | PaddleOCR | 仅 P2 弹题为图片/canvas 渲染时启用 | 多模态 LLM 直接识图 |
| 打包 | PyInstaller | 单 exe 分发 | — |
| 代码加密 | PyArmor 8（RFT+BCC 模式） | 见 §5.7 对比 | Nuitka |

LLM 配置示例（`config/settings.toml`，Key 只放环境变量，配置里写引用名）：

```toml
[llm]
base_url    = "https://api.deepseek.com/v1"   # 任意 OpenAI 兼容端点
model       = "deepseek-chat"
api_key_env = "XXT_LLM_API_KEY"
```

### 4.1 部署形态（已确认：本机 Windows 长期挂机 或 Docker，双形态支持）

- **Windows 先行（P0/P1 首选）**：有头浏览器便于首次登录与验证码人工介入；长期挂机需设置电源计划不休眠、断电自启（任务计划程序）
- **Docker（多账号稳定后再做）**：基于 Playwright 官方 Python 镜像（自带 headless Chromium）；`data/` 挂载卷持久化（SQLite、storage_state、日志）；配置经挂载文件/环境变量注入；`restart=always` 保证宕机自愈
- **代码不感知形态**：路径一律相对 `data/`；日志强制 UTF-8（避免 Windows 容器乱码差异）；首登录流程在 Docker 下可通过 ` headed 模式 + 端口转发/截图` 或先在 Windows 上生成 storage_state 再拷入容器

## 5. 关键模块设计

### 5.1 登录与会话管理（session/）

- **登录方式（已确认）**：学习通账号密码**直接登录**（手机号/账号 + 密码），不经过学校统一认证
- **首次登录**：有头（headed）浏览器打开登录页，人工输入账号密码/验证码（或程序代填、人工只处理验证码），登录成功后保存 `storage_state.json`
- **后续运行**：加载 storage_state 直接进入学习空间；启动先做"会话有效性探测"（访问个人信息页判断是否被踢到登录页）
- **自动重登**：检测到会话失效时，用库中加密保存的账号密码自动重新登录（受下方"登录预算制"约束）；出现验证码/风控页则转人工介入并告警（不硬闯）
- **滚动续期（防频繁登录核心）**：每次运行结束把浏览器最新 cookie 回写 storage_state（平台会滚动刷新 cookie，回写即续期），正常可数天至数周免登录
- **登录预算制**：每账号 24h 内真实登录 ≤1~2 次；重登失败（密码错/验证码）立即进入冷却并转人工，绝不连续尝试——频繁登录与连续试密是最典型的机器特征
- **长会话模式**：一次登录后在同一浏览器上下文内连续学习至当日额度完成，避免反复起停流程
- 会话探测只访问轻量页面（个人空间页），**不用登录页做探测**
- 凭据与 storage_state 存放于 `data/` 目录，**不进 git**

### 5.2 课程发现与任务生成（adapters/ + core/）

- 课程列表：复用页面自身接口（courselistdata）抓取入库（M1 已实现，`xxt courses`）
- **章节树按需抓取（最小访问原则）**：不预抓全部课程的章节树，学哪门课才进哪门抓；抓取时读取平台"已完成"标记（新版章节树 `.icon_yiwanc`）→ `done_on_platform`，入库即区分 `done / pending`，**已学章节天然跳过**
- 任务落库，章节状态机：`pending → learning → done / failed(可重试)`；重复同步章节树时需刷新 status（平台侧完成的要覆盖本地 pending——upsert 需带 `status=excluded.status`，M2 收尾项）
- 支持断点续跑：程序重启后从库中读取未完成任务继续

### 5.3 视频学习（core/video_player + adapters/chaoxing/inject/watcher.js）

**执行形态：外层编排 + 页内 watcher（混合架构）**

- **外层 Playwright**：登录、进入课程、任务调度、监控与异常恢复、**切节节奏决策**（拟人化挂点）
- **页内 watcher**（注入课程播放页的脚本，复用 xuexitongScript 经验重构，见 §5.8）：定位嵌套 iframe 内真实 `<video>`、播放与保活、识别章节树与当前节点、事件上报
- **通信**：watcher 经 `window.postMessage` / `page.exposeFunction` 上报事件（`playing / ended / stalled / paused / error / quiz-popup`），外层按节奏策略下发指令（`play / next_unit / rate`）——页内只执行不决策

两种进度模式，**P0 默认真实播放**（最稳、风控最低）：

1. **真实播放**：由平台播放器自然播放、自然上报进度心跳；**绝不跳帧/篡改 currentTime**（学习通可检测跳秒）；静音播放规避自动播放策略
2. **接口直报**（P1 可选优化）：逆向进度上报接口模拟心跳。速度快但需持续维护签名逻辑，默认关闭

watcher 保活职责（源自 xuexitongScript 实战验证）：

- 巡检恢复：被暂停 → resume；进度停滞（currentTime 连续 7s 不前进）→ resume
- 静音降级：`play()` 被自动播放策略拦截时降级为 muted 播放
- 防后台暂停：hook `visibilitychange` / `blur` / 播放器 `mouseleave`（平台在失焦、鼠标移出时会暂停视频）
- 播放 `ended` 只上报外层，由外层按拟人节奏延迟后切下一节（不用固定延时）

倍速策略：默认 **1.0~1.25x 随机**、可配置；不默认 1.5x——完成时长异常短是明显机器特征（参考项目默认 1.5x，此处不采纳）。

### 5.4 弹题检测与 AI 作答（ai/ + core/quiz）——后置到 P2

> **状态说明（v0.2）**：用户确认弹题**计分**、由 AI 识别处理，但功能后置到 P2（多账号之后）实现。
> 因计分，正确率要求高：实现时**半自动校准期必须先行**，题库优先策略加强。
> P0/P1 阶段弹题出现时按平台默认行为处理（如暂停等待），`quiz.enabled` 默认 `false`。

```
视频播放中
  → 检测弹题（注入 MutationObserver + 轮询兜底，识别题目弹层选择器）
  → 解析题型：单选/多选/判断/填空 + 题干 + 选项
  → 作答管线：
      1) 本地题库命中（题干 hash 查询）→ 直接用已验证答案
      2) 未命中 → 组装 prompt（题干+选项+题型+可选课程上下文）→ LLM
         → 要求结构化 JSON 输出（答案+置信度）
      3) 置信度低于阈值 → 先尝试页面内搜索答案线索；仍低 → 提交默认项
         或跳过并标记"待人工"（可配置）
  → 提交答案 → 读取判题结果
      → 对：答案写入题库（含正确标记）
      → 错：记录错题；若有重试机会则换答案重试（排除已错选项）
```

- 题库表：`questions(question_hash, platform_qid, stem, type, options, answer, correct_count, wrong_count)`
- 图片/Canvas 渲染的题目：截图 → PaddleOCR / 多模态 LLM 识题 → 走同一管线

### 5.5 拟人化与风控（core/stealth）

核心原则：**节奏随机而非处处停顿**——真人既有连刷也有走开，机械的"每节固定停 N 秒"本身就是机器特征。所有节奏参数一律做成配置区间（min/max），运行时按分布抽样，代码中禁止固定 sleep 值。

- **切节间隔分布（示例，均可配置）**：约 70% 概率 3~15s 连看；约 20% 概率 30~90s 短歇；约 10% 概率 3~10min 离开
- **专注会话模型**：连续学习 25~60 分钟 → 休息 5~15 分钟，模拟真实学习节律
- **多门课程穿插（v0.8）**：一天内可学多门课程（默认 1~3 门随机，更像真实课表），但**同一时刻严格只有一个任务点在播放——硬约束，硬编码不做配置**：两路并发视频进度流是物理上不可能的人类行为、最强机器特征之一；切课间隔比切节间隔长一档（"换课=换脑"，休息几分钟到几十分钟）
- **每日窗口与双额度（v0.9 已落地为 `[quota]` 配置）**：仅在拟人时段学习（默认 08:00–23:00，可配置）+ **双额度任一达标即停**——`daily_minutes`（默认 240 分钟）与 `daily_tasks`（默认 60），实际额度按 `float_ratio`（默认 [0.7, 1.0]）每日抽样浮动；两维度互补：时长控总耗时，任务数控"单日完成知识点条数"（平台侧比时长更显眼的指标；短视频课程若只控时长会刷出海量任务点）。**口径：按"账号×天"计——当日穿插的多门课程共享同一份额度，每日重置，账号之间互不影响**；不天天精确顶格（每天恰好等于上限同样是机器特征）；启动时间在计划点上加随机抖动（±0~30 分钟）；杜绝凌晨匀速刷课与 7×24 不间断
- **低频小动作（可选，默认低频）**：播放中偶尔暂停几秒再继续（每 30~60 分钟 1~2 次），过度模拟反而异常
- 登录侧防封：滚动续期 + 登录预算制 + 长会话（见 §5.1）
- 每账号独立 browser profile（P1 再加独立代理/指纹、窗口尺寸微差）
- **熔断退避**：检测到风控页/验证码轰炸/连续异常 → 当日暂停该账号并告警，绝不硬闯；恢复需人工确认或次日自动

### 5.6 多账号统一管理（P1，已确认需求；scheduler/ + panel/）

- **账号池**：`accounts` 表，账号密码与 cookie 字段 AES-GCM 加密存储；主密钥来自本机密钥文件/环境变量（密钥文件不随程序分发）；用户自己统一增删管理
- **并发模型**：每账号一个 BrowserContext（同一浏览器实例内隔离，资源占用远低于多浏览器），全局信号量限制**同时学习的账号数 N（可配置）**
- **调度器**：按账号生成任务队列；支持优先级、每日额度、失败重试（指数退避）
- **账号级作息与额度（v0.6，配置三层模型——只有一份真相）**：
  - **全局默认**：`config/settings.toml`（窗口/时长/任务数/倍速区间等）兜底所有账号；
  - **账号级覆盖**：存 **DB accounts 表字段**（`window_start / window_end / start_at / daily_max_minutes / daily_max_tasks`，可空，空则回落全局默认）——账号动态增删，不放 toml；
  - **编辑入口**：P0 用 CLI（如 `xxt account set <账号> --window 09:00-22:00 --start 19:30 --max-tasks 30`），P1 面板只是该 DB 的可视化编辑界面，**不是第二份配置**；
  - **启动即抖动**：`start_at` 为基准，实际启动加 ±0~30 分钟随机，不每天准点开跑；
  - **账号间自动错峰**：调度器可为每账号自动分配互不重叠/部分重叠的作息（随机窗口 + 随机 start），用户手动设置覆盖自动值——多账号整齐划一同时开跑是集群特征，作息各异是最好的掩护
- **课程轮换调度（v0.8）**：
  - **优先级按"账号×课程"配置**（P1 时 courses 表增加 `account_id` 与 `priority` 字段；CLI `xxt course set <课> --priority high`，面板同源编辑）；**未完成度（pending 占比）由程序从进度库实时计算，不暴露为配置**；
  - 轮换算法：`权重 = 优先级档位（高3/普通2/低1/未设1.5）× 未完成度`，按权重**随机抽样**选下一门（不硬取 top-1，避免机械地总学同一门）；当日课程数达上限后只在已学课程中继续；切课时机=专注会话结束的休息间隙；**零配置时即自动均衡轮换，配置只是覆盖**；
- **章节级选点策略（v0.10，默认顺序、可配置跳章）**：
  - **默认：课程内顺序推进**（按章节 idx 取首个 pending，"下一节"按钮串联）——最稳、进度同步最简单，作为默认形态；
  - **章节优先级（可配置，实用优先）**：chapters 表增加 `priority` 字段（账号×课程×章节）；CLI `xxt chapter set <课> <章> --priority high`，面板同源编辑；调度时优先推进高优先章的 pending 叶子（"先看快考试的章"）；
  - **低概率随机跳章（拟人化调剂，默认克制）**：小概率（约每日 ≤1~2 次）不取紧邻的下一个叶子，而从 pending 中选一个非相邻知识点经章节树直接进入（点叶子即触发 `toOld`，技术现成）——模拟真人"翻回去/跳着看"；幅度与频率必须受限，机械乱跳反而异常；
  - **前置核实项（实现跳章前必须实况验证；随 M3 整课实跑顺带做，不额外侦察）**：① 乱序完成的进度是否正常计入并打完成标记；② 该课程教师端是否设置"章节锁定/须按序完成"；③ 跳章后"下一节"按钮的行为（接着跳入点顺序推进，还是回到全局顺序）——③直接决定调度器实现方式；
  - 不做"回看已学章节"（白耗额度、收益低）；
- **并发执行模型（v0.13 定稿：M4 一步到位 async，多进程为逃生舱；推翻 v0.12 的"多进程优先"）**：
  - **决策修正依据**：M4 本就需要多账号实机验收，async 移植后的行为复验与该验收是**同一批实跑、无额外成本**；终态本就是 async（单机 Windows/Docker + FastAPI 异步面板 + 几十账号目标），绕道多进程等于造一个注定废弃的中间层；sync→async 移植是机械的（Playwright sync API 官方即 async 的生成包装），核心逻辑（额度/节奏/轮换/章节解析）全为纯 Python **零改动**，只移植执行层（Playwright 调用与事件泵加 await）；
  - **async 落地要点**：① **结构化并发**——每账号一个 asyncio 任务（TaskGroup）+ 全局 supervisor 失败退避重启，单账号崩溃只取消自身任务不传染；② **全局协调 trivial**——`asyncio.Semaphore` = 同时学习账号数 N；错峰 = 各账号任务按自身作息 await 到点再动（非外部定时拉起）；当日额度视图进程内共享 + DB 持久化；③ **一个浏览器实例 + N 个 BrowserContext**（按需惰性创建，配合错峰常时仅 3~6 个活跃；每 context 独立 storage_state / **context 级代理**（Playwright 原生支持，接 v0.8 每账号绑定）/ UA 与窗口尺寸微差）；④ FastAPI 面板与调度器同生态（同进程或经 DB/WebSocket 解耦，实时日志异步推送）；
  - **多进程 = 逃生舱**：若 async 移植遇阻（如 Windows 事件循环与 Playwright 兼容问题）临时顶上，不作正式交付；
  - **移植纪律**：同步 StudyRunner 保留至 async 版通过同一套验收（整课实跑 + 测试全绿）后删除，期间作为行为参照——避免两套执行引擎长期并存；Playwright 同步 API 禁跨线程，多线程方案仍然排除；
- **多账号代理策略（v0.12，方案先行、按需落地——小规模家宽直连即可，不引入任何代理）**：
  - **分层按账号规模选型**：≤5 个 = 家宽直连（同 IP 少量账号是正常家庭场景，0 成本）；5~15 个 = 家宽 + 1~2 张国内 4G 流量卡分流；15~50 个 = 多张 4G 卡（每卡绑 5~8 个账号）或**按时长计费**的独享静态住宅代理；50+/商业化 = 住宅代理池（每 1~2 账号一 IP）；
  - **4G 出口是优选**：运营商 NAT IP 后面本就有大量真实学生（同 IP 多账号在移动出口属正常现象），且基站切换导致的 IP 轻微变化在移动网络是正常行为——宽容度高于家宽"绝不能变"；落地形态 = 4G 路由器 / 多网卡小主机，每张卡起一个 HTTP 代理端口；
  - **同 IP 账号密度 3~8 个**：学校机房本来就是同 IP 几十个学生，真正的风险信号是"行为同步/关联"（同时登录、相同节奏、相同课程轨迹）——错峰与随机化设计已覆盖；因此不必追求 IP 绝对唯一，按密度分摊可大幅降成本；
  - **代理抽象**：accounts.proxy 只存"每账号一个 HTTP/SOCKS5 端点"（本地端口映射或远程代理均可，来源无关）；认证凭据放 `data/` 或环境变量，配置只存引用；
  - **出口一致性自检（配套保障）**：低频调用 IP 查询服务核对每账号出口与登记值一致，漂移即告警并可熔断该账号当日学习（防"今天北京、明天广州"式跳变）；机场节点定位为次优过渡（须选国内、出口固定、用户少的节点）；
  - **成本红线**：刷课是视频流量大户（每账号每日数百 MB~1GB），**禁用按流量计费代理**，只选不限流量/按时长品类；
- **单账号多开：绝对禁止（硬编码）**：程序内同一账号永远只有一个浏览器上下文、一个播放任务；多账号并发 ≠ 单账号多开。**多端使用须知**：平台允许多端在线（手机+电脑），但程序学习时段内用户应避免在其他端看**同一门课**的视频（会产生两路进度记录）——此条在 README 与面板展示
- **IP 与设备策略（按最坏假设设计，v0.8）**：假定平台记录 IP/UA/设备指纹/行为时间序列（学习通客户端有设备信息收集被通报的公开记录）；**P0 单账号直接用家庭宽带固定 IP**（绝不换 IP，最像本人）；**P1 每账号固定绑定一个住宅型代理**（accounts 表 `proxy` 字段；禁止频繁更换、禁机房 IP——几十账号同家庭 IP 反而是集群特征）；浏览器统一系统 Chrome（channel=chrome）+ 每账号固定 profile（窗口尺寸微差）
- **参数三层分工（v0.8 固化）**：**安全底线硬编码**（单任务点、不跳帧、不硬闯风控）不做成配置；**策略参数配置化**（窗口/双额度/每日课程数/切课间隔/代理绑定，全局默认+账号覆盖）；**主观决策留给用户**（课程优先级——程序不知道哪门课要考试）
- **规模设计**：按"几个~几十个账号"设计（用户最终规模待定），SQLite 足够，预留 MySQL 升级路径
- **面板**：FastAPI + 轻量前端，功能：账号管理、进度看板、实时日志（WebSocket）、暂停/恢复

### 5.7 代码保护（P3）

| 方案 | 保护强度 | 成本 | 说明 |
|------|---------|------|------|
| PyArmor（RFT 模式 + BCC） | 中高 | 低 | 脚本加密+控制流混淆，开箱即用，支持到期/机器码授权，**推荐首选** |
| Nuitka 编译为 C | 高 | 中 | 真编译，逆向成本高；但编译配置繁琐、Playwright 打包体积大、兼容性需验证 |
| 核心逻辑服务端化 | 最高 | 高 | 答题/调度核心部署服务器，客户端只是壳。适合商业化，需运维 |

**推荐路径**：P3 先用 PyArmor 混淆 `src/xxt/core` + `ai` 包 → PyInstaller 打包 exe → PyArmor 的授权文件机制做机器码+到期绑定。若后续商业化规模大，再将核心上云。

### 5.8 参考项目分析：xuexitongScript

> 出处：https://github.com/chaolucky18/xuexitongScript （学习通自动刷课脚本，页面注入式，约 2k star，2026-10 仍活跃维护）

**形态**：油猴/控制台注入课程播放页的 JS，页内 DOM 自动化；**无登录、无多账号、无持久化、无答题**（其明确跳过章节测验）。

**可复用资产（最值钱的部分——实战验证的选择器与保活逻辑）**：

| 类别 | 内容 |
|------|------|
| 章节树 | `#coursetree`（树容器）、`.posCatalog_select`（叶子节点，`.firstLayer` 为章）、`.posCatalog_active`（当前节点）、`.posCatalog_name`（切节点目标） |
| 视频定位 | 嵌套 iframe：`iframe.ans-insertvideo-online`（深度≤2）→ `video#video_html5_api`（video.js 播放器） |
| 步骤导航 | `.prev_title`（当前步骤名）、`.prev_white`（如"2视频"页签）、`#prevNextFocusNext`（下一任务点/跳过测验） |
| 保活逻辑 | 暂停恢复、卡进度看门狗（currentTime 停滞 7s）、静音降级播放、防失焦/鼠标移出暂停 |

选择器进选择器配置，保活逻辑进 watcher（§5.3）。

**重构方向（不照搬其用法）**：

- 由"控制台粘贴 + 自毁重载"改为外层**一次性注入** + 事件桥双向通信（上报-决策模式），拟人节奏由外层控制
- 其内部固定延时（切节 1s、加载 3s）替换为外层随机节奏；去掉 jQuery 兼容与重复绑定防护包袱
- 倍速默认值不采纳其 1.5x（见 §5.3 倍速策略）

**License 注意**：若上游无明确开源协议，复用以"选择器与思路"为准、watcher 按我们的通信协议自行实现；如需直接引用其代码段，先确认上游协议。

**我们补充的能力（上游完全没有）**：登录与会话管理、多账号隔离与并发调度、课程发现落库/断点续跑、拟人化节奏、弹题 AI（P2）、持久化日志与告警。平台改版时可对照该仓库更新（其活跃度高，相当于免费的前沿情报源）。

## 8. 风险与合规（重要）

1. **平台协议风险**：自动化学习违反学习通用户协议，账号存在被警告、清进度、封禁的可能。工程上用低频、拟人化策略降低风险，但**无法归零**，需使用者自担。
2. **AI 正确性**：弹题计分，LLM 答题不保证 100% 正确。因此 P2 强制半自动校准期先行，正确率达标后才开全自动。
3. **使用边界**：仅操作自己拥有或获得授权的账号；不对平台做攻击性测试（不爆破验证码接口、不做压力请求）；P3 对外分发时注意相关法规要求。
4. **工程风险**：平台前端改版会导致选择器失效——通过适配层 + 选择器配置化收敛影响面，改版后只需更新配置/adapter。
5. **挂机环境风险**：Windows 需处理休眠/断电自启；Docker 需 `restart=always` 与数据卷持久化，避免 cookie/进度丢失。
